# 用 AI 定制 S2Arm 触屏布局

默认虚拟手柄无需配置。想调整大小、位置或单双手习惯时，把本说明、[schema](layout.schema.json) 和从自己设备导出的当前 JSON 一起交给 AI。没有导出文件时，可从 [完整参考方案](classic-reference.json) 开始；参考方案按 844×390 pt 屏幕生成，不代表所有设备的推荐布局。

先告诉 AI 目标设备、横屏方向、屏幕尺寸（UIKit **pt**，不是截图像素）、safeAreaInsets，以及想改变哪些控件。设备尺寸未知时让 AI 先询问，不要凭机型猜。系统安全区之外，运行时左右各至少留 16 pt、底部至少留 8 pt。设实际安全区宽高为 W、H，U=min(W,H)：

- 按键中心：`safeLeft + x*W`、`safeTop + y*H`；x/y 为 0～1。
- 按键宽、高和圆角：分别为 `width*U`、`height*U`、`cornerRadius*U`。width/height 是 **短边比例**，不是各自宽高比例；范围 0.04～0.4，圆角不超过两者较小值的一半。绘制框最终限制在安全区内。
- 每个可见按键热区向四周扩 10 pt，重叠时 JSON 数组中靠前的按键优先。设计时尽量留出热区间距；边缘钳制后的框也要检查。按键命中优先于摇杆。
- `A B X Y L R ZL ZR PLUS MINUS LEFT UP RIGHT DOWN` 共 14 个 id 必须各出现一次；可额外各加一个 LS、RS。大小写严格匹配，不能自创 HOME 等 id。显示文字由运行时决定。
- `sticks` 恰好包含 left/right。activation 的 x/y 是安全区中左上角比例，width/height 是安全区宽高比例，区域必须完整位于 0～1 且左右不重叠。常用左右各半屏。摇杆浮动中心取起始触点，radius 是 U 的比例，范围 0.04～0.3；保留原有双击按住触发 LS/RS。

输出 UTF-8、最多 64 KiB 的完整 JSON。顶层仅允许 schemaVersion、id、name、buttons、sticks；schemaVersion 必须是整数 1，不增加注释或其他字段。id 用 1～64 个小写 ASCII 字母、数字、点、下划线、连字符，首位是字母或数字；每个新方案用新 id，不能使用保留的 default 或已导入 id。name 为 1～64 字符，不含控制字符。schema 之外，App 还会校验缺失/重复 id、圆角、激活区边界与重叠；schema 校验通过不代表一定能导入。

可以复制给 AI 的请求：

> 请依据附件说明、schema 和我的当前布局 JSON，为我的目标屏幕生成一个完整可导入的 S2Arm schemaVersion 1 布局。目标设备、屏幕 pt 尺寸、安全区、方向与操作偏好如下：〔填写〕。保留全部必需按键与左右浮动摇杆，按键热区尽量不重叠，检查安全区钳制后的实际框。使用新的唯一 id 和可读名称，只返回 JSON 文件内容，不要 Markdown 围栏、解释、资源路径或额外字段；缺少目标尺寸时先问我。

将结果保存为 `.json`，在 App 内四指同时长按至少 1.5 秒，进入“S2Arm → 触屏布局… → 导入布局…”。导入同 id 会拒绝而不会覆盖旧文件。实际试按全部按键、左右摇杆与多指组合，再按手感迭代；遇到问题可恢复默认，自定义文件保留。导出/提交给 AI 的只有布局 JSON，无需附带游戏、密钥、存档、诊断包或设备标识。

# G01：任务错误与恢复

关联 #58 / G01。覆盖 Mac 任务系统中的密钥、输入、空间、权限、开发环境和已知版本限制，复用现有诊断卡片、日志入口和重试流程。

## 错误码

错误码由失败出口显式指定，系统 I/O 错误按 errno 判断，不从任意报错文案猜测原因。恢复指引统一定义在 `pack/jobs/errors.py`，英文显示沿用启动器的 `Localizable.json`。

| 错误码 | 含义及处理 |
|---|---|
| `keys_missing` | 尚未导入玩家密钥，在设置中导入后重新放入游戏 |
| `keys_invalid` | 密钥格式、长度或重复条目冲突，重新选择完整文件；旧密钥不替换 |
| `ticket_missing` | 内容对应的票据或标题密钥缺失，核对源文件是否包含票据 |
| `content_truncated` | 已确认部分内容超出文件末尾，重新复制完整的源文件 |
| `keys_outdated` | 读取器报告缺少该内容所需的通用密钥，换一份版本更新的、你自己的 prod.keys 重新导入 |
| `content_unreadable` | 读取器明确报告无法解密或校验，核对密钥匹配性与文件完整性；不能仅据此确定是哪一种原因 |
| `input_type_unsupported` | 所选内容类型不是 NSP/XCI 或文件夹，重新选择输入 |
| `input_empty` | 所选文件夹没有 NSP/XCI，检查目录后重新导入 |
| `input_missing` | 所选输入、托管文件或任务所需目录不存在，连接磁盘或重新导入 |
| `input_base_missing` | 只有更新或 DLC，补入对应本体 |
| `guest_isa_unsupported` | 32 位 ARM 游戏暂不支持，重试无法解除限制 |
| `content_invalid` | 元数据、托管副本或内容校验失败，核对原始文件后重新导入 |
| `disk_full` | 已有空间检查拒绝，或系统返回 ENOSPC/EDQUOT，释放相应磁盘空间后重试 |
| `permission_denied` | 系统拒绝访问或写入、只读文件系统，检查文件权限和系统隐私授权后重试 |
| `architecture_unsupported` | 当前路径需要 Apple Silicon Mac |
| `os_unsupported` | 当前游戏路径需要 macOS 26+，更换支持环境后重新检查 |
| `xcode_unavailable` | 完整 Xcode 或所需平台 SDK 不可用，去 App Store 安装、打开并完成设置后重新检查 |
| `xcode_setup_required` | 已有探针识别到许可未完成，打开 Xcode 完成设置后重新检查 |
| `metal_unavailable` | Metal 编译组件不可用，安装组件后重新检查 |
| `dotnet_unavailable` | 开发 SDK 或内置运行时不可用，补齐依赖/恢复完整应用后重新检查 |
| `dotnet_sdk_missing` | iPhone 出包缺 .NET SDK，在设置中安装后重试同一 iPhone 出包操作 |
| `reader_unavailable` | 读取工具未准备或已失效，开发模式重新准备工具，完整应用重新安装 |
| `engine_incomplete` | 源码目录不完整，选择完整源码或恢复完整应用 |
| `tool_missing` | 所需工具无法启动或环境检查发现缺失，补齐工具后重试 |
| `target_required` | 未连接也未选择设备，或存在多个不同目标，连接设备或选择目标机型及系统 |
| `target_unsupported` | 目标 GPU 早于 A14/M1 或系统低于 iOS/iPadOS 26，不可直接重试解决 |
| `xcode_sdk_too_old` | 目标系统比当前 Xcode 的 iOS SDK 新，更新 Xcode 后重新检查 |
| `runtime_invalid` | 运行版本/清单/产物不完整或校验失败，保留存档并重新打包 |
| `tool_exit` | 工具异常退出，保留真实退出码及日志；尚无足够证据进一步归类 |
| `job_failed` | 未分类错误，保留日志与失败阶段供定位 |

环境检查的 `checks[].diagnostic` 与游戏目录的 `games[].requirementDiagnostics` 为可选字段；旧前端可以忽略，新前端在缺少它们时仍能读取旧数据。原有 `missing` 文案列表保留。

完整应用（请求含 `engineBundle`）的恢复指引只说明玩家可以执行的步骤；源码开发请求使用 `DEVELOPMENT_RECOVERY` 的工具/SDK 指引。Xcode 由启动器自动查找最新版，指引不要求玩家选择 Xcode。环境检查行保留原有一句话和修复按钮，不额外显示错误码、重复建议或日志按钮；诊断数据保留给诊断包和摘要使用。

## 错误如何传递

```text
失败出口 → Failure(code) / 系统 errno → Context.report_failure
                                      ↓
                         诊断事件 + 任务记录 + 最终结果
                                      ↓
                         原有错误卡片、复制摘要、对应日志
```

所有最终结果携带当前诊断列表。读取器明确给出更具体原因时，只替换相同阶段、相同日志的通用 `tool_exit`，并保留退出码；其他阶段的错误和警告不丢弃。消息与日志摘要在进入事件和最终结果前脱敏，未运行子进程的失败也生成单独的错误日志。

后台读取子进程输出、写日志或执行 `on_line` 回调时发生的异常会传回任务线程；子进程仍运行时，沿用既有安全进程组清理后再报告失败。子进程正常退出也不代表输出处理成功，读取线程结束后仍须核对其异常，防止任务被误记为完成。回归覆盖快速退出、运行中清理、管道读取异常以及真实工作进程的最终失败事件和落盘记录。

Python 和 Swift 两侧的脱敏规则覆盖名称含 `key/kek/seed/secret/token/password` 的赋值，以及 title.keys 的「32 位十六进制 = 32 位十六进制」行；独立的 32 位 NCA 编号仍保留用于定位。密钥读取提示沿用内测走查文案，包含更新 Switch、重新导出密钥、在设置中导入以及文件不完整时重新复制的步骤。

环境检查失败仍是一次成功完成的检查，检查项标失败并提供具体诊断；修复后重新检查，成功项不再携带旧诊断。失败任务记录保留，重新执行创建新记录，避免改写历史证据。

## 验证

```sh
python3 -B -m unittest discover -s pack/jobs/tests -v
S2A_DEVELOPER_DIR=<Xcode的Contents/Developer> bash launchers/macos/test.sh
```

`test_error_recovery.py` 使用临时游戏库和合成读取器，经真实 Python 工作进程覆盖：无效密钥→重新选择成功、缺密钥→导入→重试成功、无法读取→更正输入→成功、类型/空目录/缺文件区分、空间及权限故障解除、通用错误替换与退出码保留、诊断落盘和事件脱敏。合成输入不是商业游戏可玩证据。

Swift 的 `DiagnosticsTests` 覆盖最终诊断替换、旧/新检查项解码、游戏前置诊断及旧数据回退、iPhone 任务重试保持原操作。完整 UI 验收在支持的 macOS 上执行：

1. 导入无效密钥，核对 `keys_invalid`、恢复步骤及对应日志；重新选有效文件，确认可继续导入。
2. 导入只有更新的合成目录条目，核对缺本体诊断；补齐本体后重新加载目录，确认可打包。
3. 使用缺失 Xcode、未完成许可、缺 Metal 组件的环境，核对原有提示及处理按钮；诊断包中应保留具体错误码，修复并重新检查后旧诊断消失。
4. 对打包中的磁盘不足/权限错误，核对日志；释放空间/恢复访问后重试，检查旧成功版本和存档保留。
5. iPhone 出包失败后点击重试，确认仍为 `ipa` 操作；分别在中英文界面核对错误码、建议和日志入口。

维护者已在 macOS 26.4 / Xcode 27.1 对初版 `37abef36` 补验：Python 51/51、启动器 release 编译、XCTest 24/24 与输入检查均通过。本机为 macOS 15.7.7、Xcode 26.3，无法运行依赖 SwiftUI 26 的整套 XCTest；审查修订后的最终提交仍需维护者复验，初版读数不代替新提交验收。

审查修订及输出线程异常补充回归在本机验证：Python 61/61 通过，包含 4 项输出/回调异常传播回归；启动器 release 与测试目标编译通过，生产 `TaskDiagnostic.redact` 在只依赖 Foundation 的独立执行中通过 18 个合成用例，新增 2 项 XCTest 脱敏用例已编译。该独立执行只验证脱敏函数，不代替整套 SwiftUI/XCTest 或界面验收。

## 范围与回退

不修改空间预算算法（G03）、键鼠预设（F06）、Android 编排（A-W8）、原生执行或渲染器。无新增依赖、后台服务或网络接口，不自动修复环境或自动重试，不迁移游戏库、密钥或存档格式。回退本提交即可恢复原行为，不需要修改玩家数据。

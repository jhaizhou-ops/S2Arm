# F01：触屏布局格式与方案管理

状态：v1 候选实现，供 F02/F03/F04 对接；已在 iPad mini 6 的独立输入工作台完成布局管理、多指和生命周期验证。iPhone、实体手柄及真实游戏验收待补，不标记 F01 完成。

## 格式与坐标

- [结构 schema](../ios/layouts/layout.schema.json)；[完整参考方案](../ios/layouts/classic-reference.json)；[AI 使用说明](../ios/layouts/AI使用说明.md)。
- JSON UTF-8，普通文件，最多 64 KiB。顶层恰好包含 `schemaVersion`（整数 1）、`id`、`name`、`buttons`、`sticks`；不接受未知字段。
- `id` 为 1～64 个 ASCII 小写字母、数字、`.`、`_`、`-`，首字符必须为字母或数字。`default` 与 `touch` 保留给内置方案（默认布局 / 触屏直通，见 [触屏直通](触屏直通.md)），外部导入不能占用。`name` 为 1～64 个字符，不接受控制字符。
- 坐标原点在安全区左上角，X 向右、Y 向下。安全区取 UIKit safeAreaInsets；左右至少各留 16 pt，底部至少 8 pt。尺寸变化后重新投影，旧触点清空。
- 按键 `x/y` 是中心在安全区宽/高中的比例，范围 `[0,1]`。`width/height` 与 `cornerRadius` 以安全区**短边**为单位，保持圆形和尺寸比例；尺寸范围 `[0.04,0.4]`，圆角不能超过较短边的一半。绘制框整体钳制在安全区内。按键热区在可见框四边各扩 10 pt，重叠时按数组顺序优先命中。
- 按键 id 对应现有 Npad 位序：`A B X Y LS RS L R ZL ZR PLUS MINUS LEFT UP RIGHT DOWN`。除 `LS/RS` 可选外，其余 14 个必须齐全、不得重复；显示符号由运行时决定。
- 左右摇杆各一个：`id` 为 `left/right`，`activation` 是安全区中的左上角 `x/y` 和 `width/height` 比例，必须完整位于 `[0,1]` 内且两个区域不得重叠；`radius` 是短边比例 `[0.04,0.3]`。
- 摇杆为浮动模式，中心为激活区内的起始触点，超半径钳制到满量程，输出上为正。可见按键优先于摇杆；区域之外不激活摇杆。沿用双击后按住触发 LS/RS（间隔 <0.3 秒、距离 <40 pt），取消触摸不保留双击候选。
- 按钮最初触点归属确定后保持到释放，十字键可在方向间滑动；一根摇杆同一时刻只认一个触点，多指可组合其他按钮与另一根摇杆。

结构 schema 仅表达 JSON 类型及字段范围；重复/缺失 id、圆角比例、激活区边界及重叠关系由生产加载器继续校验。跨字段几何边界允许 `1e-12` 的归一化浮点误差，避免 Foundation JSON 往返舍入拒绝合法默认布局；数值类型和单字段上下界仍严格校验，绘制圆角仍钳制到框内。schema 通过不等于文件一定能加载。

内置“默认布局”按当前屏幕生成，保留原布局的点尺寸和相对锚点，并将控件框限制在安全区。参考 JSON 按 844×390 pt、安全区左/右 47、底 21、顶 0 生成，用来解释所有字段；它是可以导入的自定义方案，随短边缩放，不承诺在任意屏幕与内置默认逐点重合。F02/F03/F04 请使用各自唯一 id，并以实际操作结果调整数据。

## ZL / ZR 按住锁定

手指按住 ZL 或 ZR 满 2 秒切成锁定：松手后游戏仍收到按下，键上的小锁变成闭锁并轻震一下；再点一下，抬手时解锁、小锁变回开锁并轻震。功能开着时小锁常驻，关闭后不显示。手指按着期间已发按键不变，失焦、接实体手柄、打开设置都会清掉锁定。默认开启，在游戏库“虚拟手柄”或游戏内“触屏布局”里按游戏关闭，存为 `VPadLayouts/.hold_lock.json`（schemaVersion=1、enabled 为 JSON 布尔）。震动跟随“触感反馈”开关。

## 虚拟按键触感（C01 第 1 项）

“触屏布局”的“按键显示与触感”提供“触感反馈”开关，默认开启，按 App 持久保存。在支持触感的设备上，虚拟按键新按下或每根浮动摇杆本次手指按住期间首次到物理半径边缘时请求一次 UIKit 轻反馈。持续按住、松开、同一手指退回中心再到边都不重复；松手后下一次推杆重新允许到边反馈。左右摇杆独立记忆，同一批触屏快照的多个新事件合并成一次反馈。十字键滑向新方向也属于新按下。取消、失焦、切布局、开设置或实体手柄接管时随触点一起清空反馈状态。

该开关仅控制虚拟手柄 UI 反馈，不改变游戏自身 / 实体手柄的震动设置；仅触屏直通不触发。配置独立存为 `Documents/VPadLayouts/.haptics.json`（schemaVersion=1、enabled 为 JSON 布尔），旧布局不增加字段，不随布局导出。无文件默认开启且不写盘；坏文件保留并显示诊断，重新设置成功后原子替换；保存失败保留原值并报错。设置反馈不登记手动布局或切换输入模式。

`UIImpactFeedbackGenerator` 只在主线程触屏快照处理、`s2a_pad_update` 返回并释放输入锁后调用；不使用游戏震动的 CoreHaptics 引擎 / 锁。主机测试验证触发判据和设置读写，不能证明真实马达有反馈：硬件是否支持、系统设置是否允许、实际强度、两款游戏各 2 分钟录像及 padrec 仍须真机补验。

## 摇杆手感（C01 第 2 项）

“触屏布局”的“摇杆手感”提供三个滑块，左右摇杆共用：径向死区默认 8%（范围 0–40%），外圈饱和默认 100%（50–100%），响应指数默认 1.00（0.50–3.00）。死区用于过滤落点附近微动；外圈饱和越小，越早推满；指数大于 1 让中心更细，小于 1 让中心更灵敏。松手保存，下次推杆生效。恢复出厂手感时把三项设回 8% / 100% / 1.00；恢复布局不会重置手感。

手感单独保存在 `Documents/VPadLayouts/.stick.json`（schemaVersion=1，deadzone / saturation / exponent），不增加旧布局五字段结构的字段，不随导出布局携带，也不切换按键 / 仅触屏模式。记录缺失使用默认值且不写盘；损坏 / 类型错误 / 超范围 / 超过 4 KiB / 非普通文件会显示诊断并保留原记录；重新设置成功后才替换。写失败保留原内存值并报错。

设触点到初始落点的距离除以摇杆半径为 r，死区 d、外圈 s、指数 e。r ≤ d 时为零，否则输出长度为 `min(1, (r-d)/(s-d))^e`，方向不变；传给 HID 时才翻转 UIKit Y 轴。默认 r=0.54 输出 0.50，指数 2 输出 0.25；d=0.08、s=0.8、r=0.44 输出 0.50。触屏仅应用一次映射，实体手柄仍走 `s2a_pad_stick`。底座沿用手指落下立即显示、结束 / 取消清除的行为，旋钮仍跟随原始位移，LS / RS 点按的移动距离也仍取原始触点。

主机公式 / 存储回归和 iOS 源码语法检查不能代替真机手感。第 2 项两款游戏各 2 分钟的改前 / 改后录像与 padrec，以及真机滑块、VoiceOver、进后台归零和实体手柄切换仍须补验。

## 玩家操作

在游戏画面中四指同时长按至少 1.5 秒，打开现有的 S2Arm 菜单，再点“触屏布局…”打开管理页。游戏画面没有常驻布局按钮；首次使用不需要配置。

1. 选择“默认布局”、内置“触屏直通”或一个已保存方案，选择成功后立即生效并持久保存，关闭管理页。“触屏直通”不画任何按键、不响应摇杆，手指原样进 `Hid.Touchscreen`，与按键方案互斥；两套方案都只影响触屏源，不改手柄协议。
2. “导入布局…”通过系统“文件”选择 JSON，校验并保存后选中它。相同 id 一律拒绝，原文件不覆盖；修改 JSON 中的 id 后可作为新方案导入。
3. “将当前布局另存为…”输入名称，生成新 id，保存副本并选中；可导出后编辑 JSON。拖动调整见下方「编辑按键位置」。
4. “导出当前布局…”通过系统“文件”保存 JSON。导出内置默认时生成可导入的用户 id；不导出任何游戏资源或存档。
5. “恢复默认布局”需要确认，只切换当前选择，自定义文件保留。
6. “按键显示 → 闲置透明度”可设为 0–100%，默认 25%。停止操作 3 秒后按键降到该值；碰屏恢复高亮，设定值高于 75% 时也不会因碰屏变暗。0% 会完全隐藏闲置按键。松开滑块后保存，写入失败会提示并保留原值；只改变显示，不切换输入方案或修改按键热区。

闲置透明度单独保存在 `Documents/VPadLayouts/.visibility.json`（`schemaVersion: 1`、`idleKeyOpacity: 0–1`）。原有布局 JSON、选择记录与导入/导出格式不变；布局导出不包含此项外观设置。没有记录时使用 25%；损坏、超限或未知字段的记录保留并在设置页提示，暂用 25%，玩家重新调整成功后修复。该设置适用于此 App 内的所有按键布局；纯触屏及实体手柄隐藏规则不变。“恢复按键布局”只恢复方案，透明度可用滑块调回 25%。

文件位于本款游戏的 `$S2A_DOCS/VPadLayouts/<id>.json`（见上方「存储位置」），选择记录为 `.selection.json`，不跨游戏自动共享。可通过已启用的文件共享访问。写入先在本目录生成完整临时文件，再移动到不存在的目标；选择记录单独原子替换。导入成功但选择持久化失败时保留已导入文件，显示错误，不误报切换成功。运行时只在加载/切换读取文件，不在 HID 线程做 JSON 或文件操作。

无用户选择时使用内置默认。选定文件缺失、损坏或版本不支持时保留文件/选择记录，在 S2Arm 菜单显示警示，暂用内置默认；管理页列出诊断，重新选择成功后恢复正常。其他无效 JSON 文件也保留并列出错误，不悄悄删除。

## 编辑按键位置（11-07 维护者：按游戏自定义）

四指长按打开 S2Arm 菜单 →「编辑按键位置…」（仅触屏模式下不显示）。进入后屏幕正中出现编辑条，按键描边变淡青；手指按住任意按键拖动，键整体钳在安全区内，多指可同时拖不同键；编辑期间触屏源不可用，游戏收不到输入。
- 「完成」：按当前位置生成本款游戏的「我的布局」（id `mine`，名称「我的布局」），原子覆盖保存并选中；尺寸、圆角、摇杆激活区照旧。保存失败弹窗说明原因，位置不变。
- 「取消」：放弃这次拖动，回到编辑前的方案。
- 「恢复默认」：只切回内置默认布局，本款 `mine.json` 保留（同管理页的恢复默认）。
- 转屏 / 安全区变化时自动退出编辑、不保存。
导入（「导入布局…」）仍拒绝同 id；只有编辑器对 `mine` 覆盖写（`S2AVPadLayoutStore replaceLayout:`）。

## 存储位置：按游戏 / 按 App

布局 JSON、选择记录 `.selection.json`、`.manual`、`.last_keys.json` 存在**本款游戏**的目录：`$S2A_DOCS/VPadLayouts/`。多款容器壳选游戏后 `S2A_DOCS = Documents/games/<游戏号>`（`runtime/src/launchctx.c`），各款互不影响、不自动套用；单款壳 `S2A_DOCS = Documents`，与原先同一目录。

## 输入与生命周期

复用现有 `s2a_pad_update/read`、InputPump 和实体手柄仲裁。布局切换、打开/关闭管理页、尺寸/安全区变化、失焦/进入后台及实体手柄切换均清空按键、双摇杆、触点及双击候选。管理页期间触屏源保持不可用；关闭后根据当前手柄/前后台状态恢复，旧手指不能自动接续。

实体手柄生效或进入后台时，触屏视图由 `controller.m` 回调隐藏并清空，不改手柄协议。连着实体手柄时按最后一次输入切换（维护者 10-24）：碰屏幕 → 触屏接管、虚拟按键重新显示（`s2a_pad_prefer_touch`）；实体手柄有按键 / 摇杆动作 → 切回手柄、虚拟按键隐藏。布局管理只影响触屏源，不暂停游戏模拟或 GPU。

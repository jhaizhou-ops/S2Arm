# 设计：新回放架构的「首用管线异步 + 有界等待 + 可恢复的首次缺画」

状态：实现中（默认关，真机 A/B 为验收前置）。对象：NVK 新回放层（`android/native/nvn/backend_vulkan.c` + `graphics/nvn/replay/rp_*`）。

## 1. 现状（已核对源码）

- iOS 首用策略（Metal，`graphics/nvn/gfx/nvn/nvn_mtl.m`）：
  - `first_skip_ok`（:8536）/ `skip_safe`（:8530）：无 storage 写 + 每个颜色/深度目标本帧 fresh + 近两帧 steady 才允许首次跳画；不满足就当场建。
  - `pso_pend_take`（:8447）：按项上限（`DM_NVN_PSO_WAIT_MS`→2000ms）+ 帧级总预算（`DM_NVN_PSO_FRAME_MS`→100ms）限时等；超时给 `late`/`stuck` 终态，后续同管线立即跳过。
  - 三段预热：开机热集 + `nvn_be_shader_prefetch` 程序后台 + 绘制点限时/跳过。QoS：prefetch = `DEFAULT`（`runtime/include/s2a_qos.h:55`），其余见角色表。
- 安卓直连旧路径已完整移植过同一套：纯逻辑件 `graphics/nvn/gfx/nvn/nvn_first_use.c`（fresh/seen 历史 + 帧预算 + `s2a_fu_wait_decide`，逐条对齐 iOS）；接线在 `nvn_vk_draw.c`（`nvk_fu_skip_safe`/`nvk_fu_*_ms`/`g_fu_budget`/late-stuck 项标）；异步建管线在 `nvn_vk_pipe_worker.c` + `nvn_vk_first_draw.c` 的 `fd_pipe_async_get/fd_pipe_drain`（提交 `f5655693`，开关 `debug.s2a.pipe_async`，默认关）。
- **差距（本任务）**：新回放层的 `nvn_gpu_pipe_get`（`backend_vulkan.c:3006`）目前把 ASYNC/PROVISIONAL 一律按 SYNC 处理（注释 :2991-2993 明说「本层 v1 不跳过任何绘制」）；`rp_draw.c:850-867` 只用 `NVN_GPU_PIPE_SYNC`，失败才 `g_skips++`。`nvn_first_use.c` 已编入 NVK 源清单但没接线。→ 首次缺管线仍同步阻塞提交线程（227ms 级长帧来源之一）。

## 2. 方案分层（不回旧架构、不引用旧代码，按新架构语义新增文件）

1. **纯逻辑待定表** `android/native/nvn/nvn_pipe_pend.c/.h`（新增）：按管线描述键记会话内状态 `NONE/COMPILING/READY/FAILED`，同键合并、有界等待、late/stuck 项标、统计。宿主单测覆盖，逐条对齐 iOS `pso_pend_state/take`。
2. **后端只查不建**：`backend_vulkan.c` 新增 `nvn_gpu_pipe_lookup(d, out)`（只 `g_mu` 下查缓存，不建）；`nvn_backend.h` 声明并更正 ASYNC 合同注释。SYNC 语义不变（预热/测试仍走 SYNC）。
3. **安卓 demand 后台构建** `android/native/nvn/nvn_vk_pipe_demand.c/.h`（新增）：
   - 提交线程 `kick(desc, prog_identity)`：先 `nvn_gpu_pipe_lookup` 命中即 READY；否则登记 COMPILING 并入有界队列，返回 PENDING。
   - 后台构建线程：`rp_shader_prog_borrow(identity)` 拿正式借用 → 用程序阶段句柄填 `desc.st[].sh` → `nvn_gpu_pipe_get(SYNC)`（装进后端缓存）→ 归还借用 → 发布 READY/FAILED。程序使用寿命仍受 P1-1 借用合同保护（不裸指针跨线程）。
   - `wait(desc, wait_ms)`：缓存命中/等到 READY 返回对象；超时返回 PENDING；FAILED 带原文。含 `debug.s2a.nvk_pipe_async`（默认 0）与 `debug.s2a.fu_item_ms/frame_ms/unsafe_ms`、`nvk_fu_budget_state`、帧号。统计进 `nvn_gpu_stats`。
4. **回放接线** `graphics/nvn/replay/rp_draw.c` + `rp_pass.c`（各少量编辑，开关默认关时行为与现状逐位一致）：
   - fresh：通道 `load==CLEAR`（含 parked clear / take_zero）与 ClearColor/ClearDepth 执行点 → `s2a_fu_rt_mark_fresh(serial, frame)`。
   - seen：一笔**真实画成**后，对该笔每个颜色/深度目标 `s2a_fu_rt_mark_seen(serial, storage, fmt, frame)`（跳过的笔不记）。
   - 取管线块：开关开时改用 `kick` + `s2a_fu_wait_decide` 循环（item/frame/unsafe 三档 + 本帧预算 + late/stuck 项标），可安全丢则 `g_skips++` 并跳过本笔；否则限时等。开关关走现状 SYNC。
   - 对 demand 的引用用**弱符号**（同直连 `first_draw` 的老做法），缺实现=退回 SYNC，不影响 iOS/鸿蒙/单测链接。
5. **统计/诊断**：跳过分类（budget/late/stuck）、提交/就绪/等待/等待毫秒、skip_safe 原因分布，随长帧日志或按 2 的幂打印。

## 3. 关键不变量与风险

- **可恢复性**：只有「无 storage 写 + 目标本帧 fresh + 近两帧 steady」才允许跳过；任一不满足就原地等/建。单凭「本帧清过目标」不足以断言最多亏一帧——**塞尔达类时域历史/曝光/阴影/遮挡查询必须真机验**。跳过的笔不登记 GPU 写者、不计 seen。
- **寿命**：后台构建全程持 `rp_shader_prog_borrow`；收尾静默判据已含借用>0（P1-1），不新增 UAF 面。
- **并发**：demand 用 `nvn_pipe_pend` 同键合并；不同配方各自建（`pipe_build` 锁外，P1-2 已保证）；发布/安装仍走后端 `g_mu` 双检。
- **默认关**：`debug.s2a.nvk_pipe_async=0`；release 属性门关着读不到→缺省关。真机 A/B 逐项开关定位。

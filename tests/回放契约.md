# 回归证据阶梯与回放契约（10-20，测试出包线牵头）

回归要证明的是「这次改动没弄坏九款」，用最便宜的充分证据。`python3 tools/gate_route.py evidence <改到的文件…>` 给出这次改动要哪一级：

| 改到哪里 | 最小充分证据 | 谁跑 |
|---|---|---|
| tools/ pack/ tests/（visual 除外）、文档 | 被波及的单测（覆盖面按引用自动推） | 门禁 |
| graphics/、compat/tree/src/Ryujinx.Graphics.*、tests/visual/ | **GAL 录像回放**：九款逐帧对拍 | 门禁（tests/visual/gate.sh） |
| services/、compat/tree/src/Ryujinx.HLE / Horizon / Audio | **IPC 录制回放**：比应答 | 门禁（services/gate.sh） |
| tests/autoplay/ | 自动玩家单测（假宿主 + 假驾驶员） | 门禁（tests/autoplay_test.sh） |
| runtime/、Makefile、*/build.mk、ryujinx 其余（ARMeilleure / Cpu / Memory / 补丁）、表外路径 | **整局**：Mac 健康表九款，每局 ≤300 秒 | 改动线合入前自己跑 |

整局只用于 native / 宿主 / 执行模型改动和验收。其余改动起整局要在成本账本里写清「为什么回放证不了」。

## 门禁路由

- `tools/gate.sh` 读 `GATE_CHANGED`（列车给出改到的文件）。
- 单测只跑覆盖面命中的。
- 钩子和 iOS 全量编译按各钩子文件头「# 门禁路由：」。哪个钩子都没声明到的代码路径一律全跑。
- 各线改了自己钩子的依赖面时，同一笔提交里改表中对应那一行。

## GAL 录像回放（画幅线，接在 tests/visual/gate.sh）

- **录像**：放在 `~/.s2arm/run/s2arm/replay/gal/<款>/`，清单 `replay/gal/list.tsv` 的列为：款、录像文件、帧号（逗号分隔）、基线来源提交。
  - 九款各至少 1 段，覆盖标题、菜单、局内代表场景。
  - 录像和基线不进仓库。
- **基线**：同一份录像用 origin/main 的 libnxgal 回放出的逐帧图。
  - 基线只在 main 前进后、从 main 刷新，分支不许写基线。
- **判据**：每帧与基线比，通道差 >2 的像素 ≤0.5%（或哈希相同）。
  - 回放错误为 0。
  - 九款并行跑，墙钟 ≤60 秒。
- **触发**：`GATE_CHANGED` 命中 graphics/、compat/tree/src/Ryujinx.Graphics.*、tests/visual/。为空时也跑（空 = 不知道改了啥）。
- **输出**：末行写「期望 九款 N 帧逐帧一致 → 真结果 …」，退出 0 为绿。
- **账本**：每次回放执行 `bash tools/cost_log.sh replay <款> <秒> <结果>`。

## IPC 录制回放（服务接入线，接在 services/gate.sh）

- **录制**：放在 `~/.s2arm/run/s2arm/replay/ipc/<款>.ipcrec`，一局从起局到 MARK 的请求序列，按调用顺序记录。
  - 每条记录：服务、命令号、请求参数与缓冲、期望应答（结果码、输出参数与缓冲）。
  - 期望应答来自 Ryujinx 真值局；没有真值时，用 main 基线局并注明来源。
- **回放器**：不起游戏，把请求按序灌进服务层（进程内），按 `tools/ipc_diff.py` 的输入格式（「序号 框架 服务 命令号 k=v…」）导出我方应答。
  - 然后执行 `python3 tools/ipc_diff.py <期望> <我方>`。
- **判据**：差异为 0；允许差异的白名单写在录制旁，每条带理由。
  - 墙钟 ≤30 秒。
- **触发**：`GATE_CHANGED` 命中 services/、compat/tree/src/Ryujinx.HLE / Horizon / Audio，或为空。
- **输出**：末行写「期望 九款 N 条应答一致 → 真结果 …」。成本账本同上，类别填 replay。

## 测试成本账本

- 每起一局（Mac / iPhone / 真值 / 回放），收局时记一行到 `~/.s2arm/run/s2arm/cost.tsv`。
  - 写入方式：`source tools/cost_log.sh; cost_log <类别> <款> <墙钟秒> <结果> [局目录]`。
  - 列为：时刻、线、类别、款、为什么、墙钟秒、结果、局目录。
- 线取 `COST_LINE`（缺省取 `MERGE_OWNER`），为什么取 `COST_WHY`，起局前 export。
- 已接入的地方：
  - `tools/dev_run.sh`（iPhone，线和说明由调度从入队参数带过来）；
  - `tools/mac_health.sh`。
- 待接入：
  - `runtime/run_mac.sh`（原生层，直接起的 Mac 局）；
  - 真值局（Windows Ryujinx）。
- 汇总：`python3 tools/cost_report.py [小时数]`，按线 × 类别列出局数、墙钟和红局数，以及「为什么」排前 10 的条目。

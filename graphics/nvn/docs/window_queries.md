# NVN 窗口只读查询（#270 B 组）

仅补 `WindowGetCrop` 与 `WindowGetNativeWindow`；`WindowGetNumTextures` 按维护者口径排除，保留未实现，不猜 ABI。

## 独立契约依据

输入为用户提供的 Cuphead 1.3.7 原始 `sdk` 模块（SDK 5.5），SHA-256 `4711973e6ce313c6024aff00614a427588f744130bd5f9152ad1e5fd279675f0`。只读解码并应用模块自己的相对重定位，没有运行原始 SDK，也没有获取外部 SDK。游戏模块、指令窗口和完整表仅保留本地。

模块内 498 个按字母排序的函数后缀，以名称块 `sdk+0x996a0c`、32 位偏移表 `sdk+0x999ed4` 和函数指针表 `sdk+0xb3ac18` 关联；全部 498 个名称偏移均逐项一致。原始 bootstrap 的内部查询按同一后缀表二分查找，再取对应指针。以下地址均相对本模块，不用于产品代码。

| 入口 | 表索引 | 实现偏移 | 只读核对结论 |
|---|---:|---|---|
| WindowInitialize | 494 | `0x3be870` | 成功路径把 builder 纹理写入 window 的纹理数组；尾段 `0x3bea50..0x3bea68` 将 x/y 清零，并把首张纹理的宽/高写入裁切宽/高。不是全零矩形。 |
| WindowGetCrop | 491 | `0x3bebf0` | 依次复制 window 保存的四个 32 位裁切字段到输出矩形。 |
| WindowGetNativeWindow | 492 | `0x3beb60` | 返回初始化保存的 native window 指针。 |
| WindowSetCrop | 495 | `0x3beb80` | 宽或高任一为零时，忽略传入 x/y，并恢复首张纹理的完整尺寸；其他情况保存给定矩形。 |
| TextureGetWidth / Height | 438 / 425 | `0x3bd940` / `0x3bd950` | 独立确认初始化尾段所读取的两个纹理字段确为宽和高。 |

因此，首张纹理为 1280×720 时，仅 Initialize 后 GetCrop 的手算期望为 `(0,0,1280,720)`；换成 640×360 后是 `(0,0,640,360)`。测试不调用生产宽/高查询或布局函数生成这些期望。无纹理的非法/不完整 builder 不作为 SDK 默认值依据。

## 生产与上屏接线

Initialize 记录完整纹理尺寸；SetCrop 的零维复位也记录同一完整矩形。两个只读查询不改变对象。无函数名/游戏地址特判。

已检查 `nvn_mtl.m` 的两条 present 裁切路径：原先零矩形代表整张纹理；现在显式 `(0,0,width,height)` 进入有界裁切分支，仍覆盖整张源纹理，坐标与尺寸相同。`widen_glue.inc` 也把旧隐式全图与新显式全图交给同一完整边界；已有宽屏修正继续作用。未删除越界报红，也未修改 GPU/present 实现。代码核对不等于 GPU/游戏画面回归。

## 测试与限制

`t_nvn_b` 通过真实 `h_nvnBootstrapLoader`、`swnvn` 注册与计数跳板调用生产 API，链接共享 NVN/宿主对象和 Widen NativeAOT，不截源码、不替换 NVN 宏。纹理也由生产 Texture API 建立懒加载 CPU 状态；没有池上传、GPU 提交或上屏。覆盖 Initialize 默认、Set/Get、零维复位、第二对象隔离、builder 改动与复位、输出宽度及对象边界。

代码/测试对应 `10c2bbbc`（后续仅文档记录）。Intel 以 SDK26.5 交叉构建真实共享 libnvn、宿主对象与 Widen NativeAOT，M1 Pro / 16 GiB / macOS27.0.1 运行相同签名与哈希的预编译文件：

| 实际生产路径副本 | 断言 | 不符 | 退出码 |
|---|---:|---:|---:|
| 正常实现 | 111 | 0 | 0 |
| GetCrop 四项改为 0 | 93 | 38 | 1（预期） |

反证只替换真实库中单个完整生产对象的对应函数内容，其余宿主、注册、签名、计数跳板与 Widen 均不变。库/测试代码不为反证修改或绕过生产宏。初次远端脚本在 zsh 参数拆分时退出，未执行测试；改用显式 sh 后上述运行完成，临时文件与专用锁均清理。五次调用总墙钟约2.01秒，非性能基准。

构造函数仍报缺 NPDM/地址护栏、无游戏程序号缺省参数；该夹具不启动游戏或保留 Switch 虚拟地址窗，不把断言通过写成日志零红或全链通过。纹理为生产 API 的懒 CPU 状态，没有 GPU 上传/渲染/上屏，不等于有效 SDK 设备上的完整 Texture/Window 生命周期。历史 92 条隔离断言只证明原宿主状态，不构成上述 SDK 缺省契约证明。未在 M1 编译或安装开发工具；Intel SDK26.5 构建与 M1 运行不等于统一 Xcode27.1 门禁或完整游戏验证。

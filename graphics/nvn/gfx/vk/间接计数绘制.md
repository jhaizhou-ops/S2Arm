# Vulkan 间接计数绘制（#271）

`vkCmdDrawIndirectCountAMD` 与 `vkCmdDrawIndexedIndirectCountAMD` 通过生产 `swhle` 表注册，设备枚举提供 `VK_AMD_draw_indirect_count` revision 2。同时实现 core `vkCmdDrawIndirect` / `vkCmdDrawIndexedIndirect` 并报告 `multiDrawIndirect`，使固定数量间接绘制与已有 `maxDrawIndirectCount` 能力一致。本片不提供 core / KHR 的 count 别名。

## 执行语义

- 录制阶段保存缓冲句柄、偏移、最大条数、stride 和索引类型；不读参数或 count。
- 每次 `vkQueueSubmit` 先统计全部 command buffer 中 AMD 绘制的参数容量，分配一块 private 线性缓冲；每条绘制按 16 字节对齐取独立区间，同一录制 command buffer 重复执行也不复用区间。无有效 AMD 绘制时不分配。
- 开始每个 render pass 前，先结束之前的 blit，再扫描本遍的 AMD 绘制，在一个 compute encoder 内打包参数。GPU 读取此前命令执行后的 `uint32_t count`，将超出 count 的条目写零；结束 compute 后才开启 render encoder。本遍绘制直接读取对应区间，结果为 `min(count, maxDrawCount)` 次有效绘制，计数屏蔽不切开 render encoder。
- core 固定数量入口直接使用原始参数缓冲。drawCount 为 1 时忽略 stride；AMD 入口仍要求有效 stride。
- Vulkan / Metal 的非索引记录均为 4 个 32 位字，索引记录为 5 个；有符号 `vertexOffset` 保留原位。内存绑定、参数、count 和索引缓冲偏移分别计入。
- 保留既有遍内拷贝兼容路径的附件恢复和活动遮挡查询分段。每个 render encoder 的查询结果先以 GPU blit 保存到独立缓冲，提交完成后按查询相加，避免下一 encoder 重置 visibility buffer；没有依赖 macOS / iOS 26 的 accumulate 属性。
- submit 临时容量超过 Metal 上限或分配失败返回 `VK_ERROR_OUT_OF_DEVICE_MEMORY`。参数范围、输入缓冲分配、内核编译或 encoder 创建失败显式报红。GPU command buffer 错误沿用生产上报路径。

该实现按 `maxDrawCount` 编码 Metal draw，每条 AMD 命令占 `maxDrawCount × 16/20` 字节后向上对齐到 16 字节，整次 submit 求和；GPU 把无效条目变成零工作量，CPU 不等待 count。`g_n_draw` 统计编码条数，不代表 GPU 最终执行的有效条数。`dm_vk_indirect_stats` 返回实际成功创建的 render encoder 数、临时缓冲数及累计分配字节数。首次使用会编译固定的 masking 内核；本片未测游戏帧率、功耗或大数量间接绘制性能。

## 遍内输入改写的支持边界

正常的遍外 GPU copy、此前 render pass 或 command buffer 产生的数据，在本遍预处理时可见。不支持本遍绘制通过自依赖屏障改写后续 AMD 绘制的间接输入：记录并累计 shader-write availability 与 indirect-read visibility 两端，包括多条屏障组成的依赖链和 `MEMORY_WRITE/READ`、`ALL_GRAPHICS/ALL_COMMANDS` 泛化位。一旦本遍已有绘制且依次出现这两端，后续有效 AMD 绘制报红；这是保守拒绝该依赖组合，不是检测到某个缓冲实际被写入。

既有非标准遍内 copy 保留原执行位置。由于图像也可能绑定到与参数相同的内存，四类 copy 之后的有效 AMD 绘制统一报红，不按缓冲句柄猜测是否别名。copy 之前的 AMD 绘制、下一遍的 AMD 绘制和 `maxDrawCount=0` 不受此限制；遍外屏障、普通附件屏障、最后一次 AMD 绘制之后的屏障不触发拒绝。

## 验证

运行方法及完整源码见 [真实 GPU 回归](../../../../tests/vk_indirect_count/README.md)。测试通过生产 Vulkan API（直连层 libnvn.a，宿主用替身）和真实着色器翻译链，在 Apple M5 Pro / 48 GB / macOS 27.0 上比较 64×64 RGBA 全图，并检查手算像素和 precise occlusion 查询。

25 组覆盖 count=0/1/超过 max、max=0、非零内存绑定及各类偏移、40 字节 stride、16/32 位索引、负 vertexOffset、非零 firstInstance、此前 GPU copy 写参数与 count、direct → indirect → direct、深度内容保存、多个独立 render pass/query，以及多 command buffer / submit info / queue submit 的临时区隔离和依赖链报红。单遍四次 AMD 绘制实测一个 render encoder、一块 176 字节临时缓冲；三个 command buffer 同次提交实测三个 render encoder、一块 528 字节临时缓冲。Metal API Validation 开启时 25 组通过。

测试已登记在 `graphics/gate.sh` 的 `vk_indirect` 子项，改到 Vulkan 前端、离线翻译链、测试或构建入口时运行；本机 `GATE_ONLY=vk_indirect` 增量运行约 13 秒。结果和反例读数随 PR 自检摘要提交；不代表哈迪斯、iOS、macOS 15 或安卓运行验收。

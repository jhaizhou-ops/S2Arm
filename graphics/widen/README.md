# graphics/widen — 通用宽屏（画幅线）

零配置把 16:9 的 Switch 画面变成 iPhone 原生宽屏：视野横向变宽（Hor+）、同比例、不拉伸，界面层保持原尺寸居中。只认数学形状与结构特征，不写死任何游戏的偏移、程序号或贴图号。

## 三层（10-19 jhz 定方向：要游戏自己按屏幕宽高比算视锥和剔除，不要显卡侧硬改留露空）
| 层 | 做什么 | 归谁 | 状态 |
|---|---|---|---|
| 一 服务层报屏幕分辨率 | 游戏查显示分辨率 / 宽高比时按屏幕报，会读的游戏自己出宽图 | 服务接入线（补丁 0035：S2A_Init 按原生层 s2a_screen_w() ÷ 1080 设，与第二 / 三层同一来源） | 已做；验证等 M0 |
| 二 自动找点 + 闭环验证 | 出包时 `scan/wide_scan.py` 扫候选，运行时逐个试改，只留通过判据的点，结果进出包产物（widen_enable.<档位>.tsv） | 扫描与判据：画幅线；跳板 / 槽页 / 命中页：原生层线 | 旧宿主试验台：动森、塞尔达、暗黑3 做通；暗黑2 游戏自己宽（靠第一层）；马车8 / 八方2 / 丝之歌没有有效点；巫师3 试验台本身崩、测不了（下表） |
| 三 显卡侧改写（本目录，下文） | 前两层没生效时兜底；露空检测 >0 报红。10-26 起没有表 = 整套放宽，`tables/<款>_<构建号>/widen_full.<档位>.tsv` 有一行「0」（闭环验出放宽会坏）才 16:9 原比例居中留黑边（10-21 曾是「有一行 1 才放宽」；直连渲染目标存储放宽根修后改，见 docs/坑记录.md）（原生层 s2a_widen_full，出图层每帧标原比例页） | 画幅线 | 马车8 / 八方2 / 丝之歌开（门禁读数 + jhz 实机）；暗黑2 / 巫师3（jhz 10-21 实机拉伸、错位、阶梯亮带）不开；怪猎 10-22 起走第二层（启用表见下） |

**宽屏已验证名单（10-26 jhz 拍板，管上面三层的总开关）**：只有 `tables/verified.tsv` 登记了「程序号 + main 构建号」的游戏开宽屏；没登记的整局 16:9 原比例加黑边，三层都不开、不调宽屏核心，不出现半宽半窄。入表条件 = Mac 闭环 + 真机截图量化过（无重影 / 拉丝 / 黑边 / 变形）。出包改写阶段（`pack/stage_rewrite.sh`）命中就往产物根写 `widen_verified.tsv`，原生层 `runtime/src/widen.c` 的 `widen_verified` 只认这个文件，在屏幕宽这个唯一源头卡：没登记 = 屏幕宽按 1920。`S2A_WIDEN_VERIFIED=1 / 0` 覆盖（闭环局、验证局按已验证跑）。满屏判据对没登记的款不报黑边。

包装层「原生宽」模式：目标宽高比 ≈ 屏幕比的贴图登记为原生宽，不放宽、不动视口；界面层读的 16:9 投影照样被改写 → 原尺寸居中，没读改写矩阵的界面层视口收进中间 16:9。

界面层越界顶点外推（`SpirvEdgePush.cs`）：所有顶点着色器一律改（`WidenShaders.Vertex`，运行时与出包离线预编同一份，各机型同一份字节）——返回前按支持缓冲 `s2a_flags.y / .z`（门限² = ((1−3‰)/k)²、外推量 = 1 − 1/k，浮点位）把画布边上及外的顶点外推，平时两个值为 0 = 原样；包装层只在「原生宽目标上读改写矩阵、片元不采样贴图或只采样 ≤8×8 小图」的绘制写非零（外推只挪顶点位置、不动贴图坐标，画布边 ±1/k 挪到 ±1 = 贴图内容连同平铺周期横向拉伸 k 倍；10-21 起横向平铺采样的大贴图不再外推——nn::ui2d 只铺一遍的整画布底采样器也是 repeat，推了就是整张底图拉伸），变化时才写（8 字节）、Ryujinx 连带写 s2a_flags 时跟踪重写。片元 y 去缩放同样所有程序一律改（`WidenShaders.Fragment`，不放宽时 render_scale[0] = 1，结果与原着色器相同）。与屏幕有关的量一个都不烘进着色器，离线库能覆盖宽屏。新架构着色器语料（shpack acnh_1e）4189 个顶点着色器全部改得了，抽 2000 个 spirv-val 1998 过，2 个原件就不过（1D 图像缺能力声明）。

### 第二层闭环规则（不按游戏）
0. 一律用产品档位跑（10-20 总指挥定）：新架构 Mac 局（`graphics/widen/scan/closed_loop.sh`，自动玩家零配置）= 产品同一档位（掌机 720p）。旧试验台跑主机 1080p 档：塞尔达 / 暗黑3 在那儿验出的点（1920 / 1600 档）在产品档位一次都不执行，iPhone 上出图仍是 16:9（测试机1 / 2 塞尔达「出图未满屏」）。游戏常在同一处按档位分支写两组尺寸（塞尔达 main+0x1152308 跳转表：1920×1080 / 1280×720；暗黑3 main+0xe7858：1600×900 与 1280×720 并排存），只验了一档等于没验。
1. 探测局（宽取 1922，近似不改行为；旧宿主一局最多 16 个代码点，分批）：只看「首次命中」，没被执行的点淘汰。
2. 单点 / 二分局（宽 2346）：判每组点对「场景目标」（绘制最多的深度附件尺寸，`tests/visual/proj_aspect.py`）与「3D 镜头宽高比」的影响。
3. 组合验证：场景目标宽高比 = 屏幕比（动态分辨率的游戏高不是 1080，按比不按宽）、出现目标比 3D 镜头（游戏的投影识别不到时看画面比例）、出图满宽（最终出图左右都有内容；塞尔达只改场景点时出图只画左 1920 列）、露空 ≤0.5%（`widen_holes.py --w0 高×16/9`，地面行口径）、0 崩、到 MARK，全过才算。
4. 取舍：全过的组里点数最少；同点数优先「带条件改」的种类（aspdiv / aspstr / seadasp 只在约等于 16:9 时替换）；界面镜头点（asp）不选，界面交包装层——例外：asp 立即数是 0x3fe38e3b（十进制 1.777778 舍入的浮点）的点在怪猎 RE 引擎里是 3D 镜头「纵向视角 → 横向」的换算，只撑宽场景不改它们是 Vert-（下）。
5. 种类（`scan/wide_scan.py` 文档串）：movz / f32 / aspdiv / aspstr / asp，10-30 加 seadasp——sead 透视投影读宽高比（改读端，参考 SavageWind 旷野之息原生移植，MIT）：所有透视投影连同由它算出的 CPU 视锥剔除一起变宽，正交（界面）不读这个字段，宿主门只在读到约 16:9 时换屏幕比；按 sead 建矩阵函数的语义特征定位（不按版本写死地址），塞尔达 / 动森 / 马车8 同一字段布局，银河 2 不是 sead 引擎没有；10-21 加 f2w——`MOVZ Xd,#hi16(宽.0f),LSL#16` 后 16 条内 `MOVK Xd,#hi16(高.0f),LSL#48` 一次拼出 float2 (宽, 高)（宽 × 高是 16:9 档，中间没有指令以 Xd 为目标；W 寄存器分两次拼的不认，多是预设分辨率表副本）。10-21 加 lytsz / capsz（宿主门）——lytsz：`LDP Sa,Sb,[Xn,#0x28]`、Xn 由前 40 条内 `LDR Xn,[Xm,#0xc0]` 取得（界面库绘制信息 → 布局 → 画布尺寸）且其间未被改写；capsz：同一函数里 lytsz 之前的 `LDP Sa,Sb,[X0,#0x50]`（拷屏控件尺寸）。门里是 16:9 档宽高对才把宽放宽。第二层放宽界面投影后拷屏控件按「画布宽 / 2」定中心错位（塞尔达ポーチ页林克被切 / 碎片）。10-26 加 aspcap / aspcaps（宽高比上限）——`MOVZ Wd,#0x1c72 / #0x5555` + `MOVK Wd,#0x4007 / #0x4015,LSL#16` 拼出 19:9 / 21:9，之后先 `FMOV Sn,Wd` 的是 aspcap、先 `STR Wd,[Xn,#imm]` 的是 aspcaps；装载时取 max(原值, 屏幕比)，aspcaps 再加 0.15 把着色器画的柔边推出屏外。自带守卫（屏幕不比上限宽就是原值），不经闭环、不看启用表，开关只由名单门管。暗黑2 main 恰好 3 处（视口边距 / 坐标钳制 / 界面边柱常量，与 d2r-mobile dm/tools/patch_nso.py 同三处），九款其余各 0 处。
   改写器换成跳板、`LDR Wd` 读值槽（写 Wd 清 Xd 高 32 位 = 原 MOVZ 的结果），装载器填 scale_w(宽) 的完整浮点位（1564.0f = 0x44c38000，低 16 位非 0，一条 MOVZ 写不出），后面的 MOVK 原样执行。
   asp 认 0x3fe38e39 / 0x3fe38e3b 两种；未启用的点值槽按原指令字还原（原生层单测 t_widen ⑤–⑨、tests/widen_sites_test.sh 合成模块核扫描 + 跳板）。
   九款现行产物根重扫（10-21）：新增 f2w 动森 183（132 个是 (960, 540)）/ 塞尔达 9 / 怪猎 5，asp 怪猎 +27、八方2 +2，其余款候选不变；四款 main 用新改写器全量改写 0 缺口。

### 界面布局数据层（`scan/ui_lyt.py`，出包时跑）
任天堂 SDK 界面库 nn::ui2d 的布局文件 .bflyt：铺满整张画布（尺寸 = 画布、平移 ≤2、祖先单位变换）的背景底，只有加宽后不拉伸任何贴图内容的才加宽到屏幕宽（10-21 口径「原生满屏不拉伸，没得补就留黑边」）：
- 纯色底（没有贴图）：宽 → 屏幕宽；
- 所有贴图层真平铺（每个贴图槽寻址 repeat / mirror，且每层贴图 SRT 横向缩放 >1）：宽 → 屏幕宽、SRT 横向 ×k——纹理周期不变、接着平铺；
- 只要有一层 SRT 横向缩放 ≤1（只铺一遍；部分平铺也算）：不加宽（加宽而 SRT 不动 = 那层横向拉伸 k 倍；10-20 版曾把这类底横向放大 k，违反新口径，已撤）。这类页面中间 16:9 原样，两侧是下层内容（同页加宽的纯色 / 真平铺底、3D 场景）或黑边。
包装层把界面投影改回原尺寸后，加宽的底正好落到屏幕边。共用材质的、同包动画驱动其变换 / 贴图 SRT 的跳过并报出。只认格式通用特征，不按游戏。显卡层越界外推只推纯色 / ≤8×8 小图，不会把不加宽的底再拉伸一次（见上「界面层越界顶点外推」）。

## 每帧镜头位姿（`CameraTrack.cs`，frames.tsv cam_* 列，自动玩家判「输入有没有驱动镜头 / 角色」用）
从写进常量缓冲的数据里认透视视图投影矩阵 VP（行存 / 列存；w 行 xyz 模 ≈ 1、x / y 行与 w 行两两正交、z 行 ∥ w 行；纯投影与正交投影不算），
取本帧「绘制最多的深度目标」上被最多绘制读到的那个当主镜头（阴影图、界面层自然落选；并列时固定取（缓冲, 偏移）最小的槽——同一份常量里常并排放本帧与早两帧的 VP），
镜头中心 = 解 [r0;r1;r3]·[C;1] = 0，前向 = w 行 xyz 归一；偏航 / 俯仰按 Y 朝上。2D 款（没有透视主镜头）标空；本帧深度目标上没有绘制（30 帧游戏重复上屏）沿用上一帧。
开销控制：不在上传时扫（10-21 起）——每 32 次绘制抽 1 次计数，只查着色器连读 4 个下标的起点，起点窗口自上次判过后内容变过（常量缓冲影子的镜头脏位）才按影子重判；上屏选主镜头前，窗口变过、本帧没再判的候选丢掉（同旧：旧在上传时就作废被覆盖的候选）。同一段常量绑定走缓存（缓存记缓冲版本）。每帧零分配（单测）。
屏幕不宽于 16:9 时包装层只观察：不改任何常量与着色器（离线着色器库照常命中）。
录像核对（galplay --cam，--cam-off 对拍开销；M5 Max）：马车8 起跑 61 帧全有镜头，z 551.279 → 549.834 → 548.335 → 546.785 → 545.183 → 543.530（随车前进单调减、前向不变），每帧 0.25 ms；动森岛 4 帧 / 帐篷 3 帧全有镜头（俯 32° / 29°），录像太短、含 JIT 预热，每帧 1.4 / 0.7 ms 是上限。

## 原理（一句话）
16:9 一族渲染目标横向放宽 k = 屏幕宽高比 ÷ 16/9，视口同乘 k；透视投影的 x 行乘 1/k。两者一乘一除，像素尺寸不变、看到的范围变宽。
k 吸附到「1920 宽多出偶数列」：2868×1320 → 2346×1080（k = 1.221875，比例误差 0.02%），居中偏移是整数 213 像素，中间 16:9 区（含界面层）与原图逐像素对齐。
各贴图放宽宽度（`WidenRewriter.WidenWidth`，10-21）：宽 × k 正好是整数（k = 391/320 时宽是 320 的倍数：1920 / 1600 / 1280 / 640 / 320）就取它——这些贴图放宽比都正好是 k，贴图里从原点起的子画布与整张、不同宽度的贴图之间换算都是整数、互拷 / 合成 1:1；
否则多出偶数列（居中偏移整数，按改写投影画的内容像素格在中心与客体对齐）。读数：暗黑2 1600×900 交换链 1956 → 1955，掌机档裁剪 1565（奇数）→ 1564；丝之歌 1024×576 若取 1251（≈ 1024k）中间三分之一差异 >8 的像素 160 → 6012，所以留 1252。
取舍：① 让 1600 宽贴图多出奇数列（355），整张 1600 宽画布的居中偏移是 177.5（半像素）。碰到的情况只有「主机档 1600×900 满画布的放宽目标」（游戏把 1600 宽整张当画布：界面层原宽居中 / 读改写投影的子视口平移都按 177.5 算（原比例页的平移取整为 178，见下文），
视口浮点能落在半像素上、剪裁 / 清条带按整数取 177 / 178，内容按半像素重采样，像素格与客体错半格）；掌机档（产品缺省）在 1600×900 里只用左上 1280×720，偏移按子画布算是整数 142，不受影响。
反过来按 ② 取 1956 时掌机档每帧从 1564 宽目标合成进交换链都要 1564 → 1564.8 重采样、裁剪奇数，产品档位更常见，所以取 ①。

## 组成
工程两个：`shader/S2Arm.Gfx.Widen.Shader.csproj`（着色器改写：SpirvEdgePush / SpirvFragCoord / SpirvCbufUse / WidenShaders / WidenIndex，出包烘焙 graphics/tools/shbake 只引它，着色器阶段键只随它变）与 `S2Arm.Gfx.Widen.csproj`（运行时：WidenFrame / WidenRewriter / CameraTrack，引前者）。10-21 拆开前改运行时宽屏逻辑也会让九款重新翻译（动森键：main 上只改 WidenFrame.cs 838dfd19 → 81cc38c0；拆后只改 WidenFrame.cs 键不变、改 shader/ 下文件键变）。

| 文件 | 做什么 |
|---|---|
| `WidenRewriter.cs` | 认投影 / 视图投影 / 逆投影（行存、列存都认）、宽高比常量对、屏幕尺寸 vec4 并改写：整段扫描（`Rewrite`）与逐单元判（`RewriteWindow` / `RewriteFloats`，只扫变了的部分时用）同一套判据。幂等：改写过的值不再匹配 |
| `CbufShadow.cs` | 常量缓冲影子：绑过常量的区间按 4 KB 页留上传字节 + 每 16 字节一位的已知 / 镜头脏 / 边缘位 + 各缓冲有效改写区间（见下「常量改写：只扫变了的」） |
| `WidenFrame.cs` | 逐帧状态：放宽贴图登记；改写区间带原值登记；界面层判定（规则 A）；非放宽目标读到改写区间时写回原值、回到放宽目标再写改写值；视口 / 裁剪 / 区域拷贝换算 |
| `shader/SpirvCbufUse.cs` | 建程序时读 SPIR-V：每个常量绑定读了哪些 vec4 下标（判「这次绘制是否真读了改写矩阵」）；`gl_Position.w` 是否恒为 1（2D / 全屏通道） |
| `gal/WidenRenderer.cs` | GAL 包装层（IRenderer 装饰）：按下表拦调用，其余直通；贴图 / 贴图数组 / 图像数组包一层，程序用弱表挂读法；尺寸对不上的调用计红 |

## 接入（显卡层，归帧率能耗线的 graphics/ 与服务接入线的 compat/，接口约定如下）
推荐做成一层 GAL 渲染器包装（`IRenderer` 装饰，套在我方 Metal 渲染器外、Ryujinx 的多线程渲染器之内），不改 Ryujinx 源码：

| `SetBufferData(buf, off, data)` | `frame.OnBufferData(buf, off, data, scratch)` 为 true 时写 scratch（线程内复用的缓冲，零分配；命中处叠了改写值），否则原样发 |
| `SetUniformBuffers` / `CopyBuffer` / `ClearBuffer` / `DeleteBuffer` | 绑成常量的区间建影子页；拷贝 / 清的目标段命中丢掉、影子作废；删缓冲连影子一起丢 |
| `CreateProgram(sources, info)` | 每段 SPIR-V 跑一次 `SpirvCbufUse.Analyze`，结果挂在程序对象上 |

| `ITexture.SetData` 往放宽贴图上传 | 首次用之前收到的上传先暂存进原宽副本，首次用时定去留：GPU 往里写（渲染目标 / 拷贝目标 / 图像存储）→ 丢副本、保持放宽（Ryujinx 建渲染目标时传的客体内存初始内容）；先被读（采样 / 拷贝源）→ 是 CPU 供图，换成原宽副本（10-20 马车8 标题背景 1920×1080 视频帧被跳过、背景全黑）。上屏不算用（10-21）：上屏说明不了内容来历，还没定去留就上屏时把暂存的 CPU 内容按 16:9 原比例页放进放宽贴图（原尺寸居中在裁剪区、两侧黑）、照放宽尺寸上屏，不定去留——交换链第一次出图早于第一次被画（录像序章）时出图参数与之后相同（暗黑2 / 丝之歌 多变 1 次 → 0）。用过之后再上传：尺寸对不上，计数报红 |
| 放宽颜色目标两侧条带 | 这一帧第一次被画之前游戏没清过它，就把中间原宽 16:9 区以外的两条清黑（首次绘制前做：不抢游戏整张清屏的载入动作）；游戏这帧自己清过（包装层按全宽发）就不清。「这一帧」按命令流里的写入顺序认：最近一次写进上屏贴图（交换链，合成收尾）之后还没写过它，才是这一游戏帧第一次画——不按上屏调用次数（10-21 马车8 比赛：上屏调用常落在下一帧场景画到一半时，按上屏次数分帧把已画好两侧的场景目标再清一次黑，之后的半透明遍盖不回来，整帧场景只剩中间 16:9 + 两侧泛光；录像 181 帧里 2 帧，改后 0 帧、其余 179 帧出图逐字节相同）。10-20 马车8 标题 / 选 Mii 页两侧大片旧画面变黑；剩两侧灰色大图标 + 白块：GAL 录像逐绘制探针（galplay --probe 300:0:-60,300）定位为程序 31（nn::ui2d 通用界面顶点着色器 f1bdb17588fd460a）画的一层带图标图案的菜单底，按视野加宽画到全宽——两侧是这层底在 16:9 之外本来就有的图案；中间被不透明的 16:9 标题大图（CPU 供图、夹边采样）盖住。不是渲染错误，是「底层 Hor+、顶层图片只有 16:9」的叠加结果；要两侧与中间一致只能把顶层图片推到屏幕边（拉伸）或两侧不露底层（黑边），属画面取舍。10-20 总指挥暂定 B：放宽目标上采样「没放宽、16:9、≥ 目标原宽 90%、横向非平铺」贴图的绘制 = 顶层整画布图片，画它之前两侧清黑、本帧之后画到这张目标的绘制剪到中间原宽区；`S2A_WIDEN_PIC=off` 切回原样。对比图 docs/研究/宽屏取舍/马车8标题_对比.jpg（jhz 定）。读数：马车8 标题录像 37440 次绘制命中 323 次、标题 / 选 Mii 页两侧纯黑；比赛录像命中 0 次、开关前后第 10 帧逐字节相同。10-21 起归入下文「16:9 原比例页」：剪到中间之外，页内绘制按 16:9 原样画（不再按 k 拉伸） |
| `GetData` / 拷到缓冲读回放宽贴图 | 尺寸对不上：计数报红（三份录像里游戏行为 0 次；序章补内容另算） |

`IBufferPatcher.Write` 必须与之后的绘制同序生效（与 `SetBufferData` 同语义）。我方 Metal 渲染器若对共享内存缓冲直接 CPU 写、不排进命令流，这条要先和帧率能耗线对齐。

## 常量改写：只扫变了的（10-21，替换「上传时扫整段」）
上传时扫整段时，暗黑3 每帧 2.1 MB 上传全扫一遍（帧率能耗线 Mac 采样：宽屏层占编码线程忙时 47%，Rewrite 约 11%、镜头跟踪约 5%）。上传的内容大半与上一次一样（暗黑3 前 300 帧：上传的 16 字节粒里内容变了的只 8.0%）。改成：
- **影子只给绑过常量的区间**（`CbufShadow.cs`）：`SetUniformBuffers` 绑到的区间按 4 KB 页建影子（上传字节 + 每 16 字节一位已知 / 镜头脏位）。没绑过常量的数据（顶点 / 索引 / 只当存储用的）不留影子，照旧整段扫。
- **上传时**：有影子的页逐 16 字节比（向量化），没变的粒不扫、那里的命中原样保留；变了的区间 [lo, hi) 只判碰到它的单元——矩阵窗口起点 [lo−48, hi−16]（往前带 48 字节）、浮点位置 [lo−4, hi)，窗口要整个落在这次上传里（同旧），先矩阵后浮点（同旧）。整段都变了（没影子 / 影子未知）走旧整段扫描（块平方快筛）。命中的改写值叠进 scratch 随这次上传发（同旧，不在绘制时另写 GPU）；写回原值 / 重新改写机制不变。
- **跨上传边界的窗口**（10-21 暗黑2）：游戏按 4 KB 一块传常量，矩阵正好跨两块时两次上传都判不了（同旧）；之后整段 8 KB 上传、内容没变，旧做法整段重扫会改上，只扫变了的却一直不判它（影子对照漏改矩阵 2）。
  修法：每次上传判完，若边界外侧那粒已知（之前传过），给上传头 / 尾 48 字节的粒置「边缘」位；下次上传盖住它们时即使内容没变也重判（不丢已有命中），判完清位。外侧未知的不置（跨界窗口那时判不了，等外侧上传时由它的边界置位），原样重传仍一个字节都不扫。
  反过来的情况（之前整个判过、改上的矩阵，之后分两块原样重传）只扫变了的保留命中、旧做法两块各扫都不含整个矩阵而不改：影子对照记「多改」，GPU 上是完整改写过的矩阵，比旧做法对。
- **别的写入**：缓冲间拷贝 / 清缓冲——GPU 上目标段换成源上已改写的内容（同旧），目标段命中丢掉、影子作废（下次上传整段扫）。GPU 写（存储 / 图像）不管：上传总是整段发、判扫不扫只看 CPU 数据有没有变，GPU 写过不影响对错。CPU 读回读到的是上传时已改写的内容（同旧）。删缓冲：影子、命中、镜头候选一起丢。
- **只读到一截的命中写回原值**（10-22 暗黑2 场景闪烁）：流式常量缓冲里旧相机矩阵的 3 列残留 + 这帧新写的逐材质块首个 vec4（如 (0.4,0,1,1)）会凑成「正交 × 视图」被改写，
  材质系数 0.4 → 0.327、调色 LUT 混合权重 0.542 → 0.444，只在数据恰好接在残留后面的帧出现 → 约 1/3 帧整片变暗。着色器用矩阵必然整块读：放宽目标的绘制 / 计算派发
  读某个命中时，若没有绑定整块读它（落在绑定里且每个 vec4 都读）、只读到一截，就写回原值（`WidenFrame.NeedsOriginal` / `RestoreFor` / `OnDispatch`）；只写没放宽图像的派发同画到没放宽的目标，全部原值。
  暗黑2 营地 SPIR-V 录像第 3–60 帧：比不放宽暗 >1 级的帧 18 / 58 → 0 / 58（同帧亮度差 [−0.27, 0]）。
- **影子回收**（10-22 暗黑2）：页按「最近一次被绑」老化，`KeepFrames`（120）帧没再绑的回收进池子（内容作废，之后上传到那里等于没影子、整段扫；命中表不动，照算读到改写）；删了的缓冲连页带命中表回收，新缓冲复用。镜头候选所在页被回收就丢候选（之后的写入不再记脏位）。
  暗黑2 常量绑定在大缓冲里一路往后挪、缓冲不停新建 / 删除：旧做法页只建不收（录像 30 帧新建 211 页、影子 37 MB 还在涨）、每个新缓冲新建一份影子，编码线程每帧约 40 KB 分配；改后稳态零分配（单测），回放保留 2 帧 / 120 帧上屏图与旧做法逐像素相同。
- **相机签名**：系数对只认已见过的签名。签名表变了（新签名加入；九款整局只变 1–6 次）就让全部影子作废，下次上传整段重扫——之前在没变的数据里判过没中的系数对按新签名重判（旧做法每次上传都重扫，迟早改上）。

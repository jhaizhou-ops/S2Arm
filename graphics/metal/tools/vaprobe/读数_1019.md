# 地址预算探针读数（测试机1，10-19 19:1x，总指挥「渲染器地址预算」第 2 条）
探针 main.m：Metal 资源建前 / 建后扫一遍进程虚拟地址区域（vm_region_64），比总量、低区（< 0x70_0000_0000）、64 GB 窗口段的变化。
签名用通配开发描述文件，**不带扩展虚拟寻址与提高内存上限**——所以这台进程没有 64 GB 窗口，但「资源占不占进程虚拟地址」不受影响。设备锁持锁 2–3 秒 / 次，跑完卸载。

| 资源 | 建成 | 进程虚拟地址增量 |
|---|---|---|
| 对照：Shared 缓冲 256 MB | 是 | +0.250 GB |
| Private 缓冲 1 GB / 4 GB | 是 / 是 | +0.000 / +0.000 GB |
| Private 缓冲 8 GB | 否（单缓冲上限 maxBufferLength 6 GB） | — |
| Private 缓冲 1 GB，GPU blit 写满并等完成后 | 是 | +0.008 GB（命令队列 / 命令缓冲本身） |
| Private 贴图 1 GB / 4 GB（RGBA32F） | 是 / 是 | +0.000 / +0.000 GB |
| Private 贴图 8 GB（2 层数组） | 否 | — |
| Private 缓冲 4 GB，GPU 写满 | 进程被杀（信号 9：无提高内存上限能力时超出内存上限） | — |

结论：Private 存储的缓冲与贴图不占进程虚拟地址空间（建出来与 GPU 写过都一样），不受 64 GB 窗口与低区空洞的限制；只受物理内存 / 内存上限与单缓冲 6 GB 上限约束。

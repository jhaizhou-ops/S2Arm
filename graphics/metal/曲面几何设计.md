# 曲面细分 / 几何阶段（第 8 块）设计 · 10-20

**目标**：用到曲面细分（hs/ds）或几何（gs）阶段的程序能正确渲染，并且全部离线预编。玩家首次遇到时零现编，满足「首遇零延迟」。这一块挡 M4，涉及马车8（gs 1 支）、八方2（gs 30 支）、暗黑2 地形（hs/ds 2 支）、巫师3（hs/ds/gs 42 支）。

**现状**：
- 渲染器不认这两类阶段，gal_prog.m 直接回「阶段不支持」。
- NxRenderer 报 `supportsGeometryShader: false`，所以 Ryujinx 运行时会把「顶点 + 几何」转成计算着色器执行。但它的磁盘缓存加载器会丢弃这类程序（ParallelDiskCacheLoader 里 `if (vertexToCompute) return;`），每局都要现翻。
- 曲面细分不走转计算，运行时程序直接建不出来，相应的东西就不画。
- 出包时 shbake 把这些阶段记为 `known_gap`（gs_unpaired / tess_unpaired / vtg_compute）：照样报红，但不计入退出码。

## 一、曲面细分：直接用 Metal 原生曲面细分

Metal 的曲面细分没有 hull 阶段，分三步：
1. 一个计算着色器写出曲面细分因子缓冲；
2. 固定功能的细分器；
3. 后细分顶点函数（`[[patch(triangle|quad, N)]]`）。

对应关系：

| Maxwell / Vulkan | Metal | 怎么做 |
|---|---|---|
| 顶点（VS，喂 patch 的控制点） | 计算核 | SPIRV-Cross `MSL_VERTEX_FOR_TESSELLATION`：顶点着色器翻成计算核，把控制点写进缓冲 |
| hull / TCS（hs） | 计算核 | SPIRV-Cross 把 TCS 翻成计算核（`MULTI_PATCH_WORKGROUP`，一个线程组跑多个 patch），写控制点输出和 `MTLTriangle/QuadTessellationFactorsHalf` |
| 固定细分器 | 渲染管线的 tessellation 设置 | 分区模式、域、绕序、最大因子都从 SPIR-V 执行模式读出来，进管线描述 |
| domain / TES（ds） | 后细分顶点函数 | `[[patch]]` 入口；用 `RAW_BUFFER_TESE_INPUT` 直读控制点缓冲；`TESS_DOMAIN_ORIGIN_LOWER_LEFT` 对齐 Vulkan 的域原点 |
| 片元 | 片元 | 不变 |

每次带曲面细分的绘制在渲染器里拆成两步：
1. 计算编码器先跑顶点核和 TCS 核；
2. 渲染编码器再 `setTessellationFactorBuffer` 并 `drawPatches`。

计算这一步放进预载命令缓冲，原理同 8785fa7 的拷贝挪前，避免每次曲面绘制都切渲染遍。如果某次绘制依赖本帧前面的 GPU 写入，就退回在当前位置切遍；这种情况单独计数，作为红项上报。

**缺口**：
- Metal 没有 isolines 域。遇到就照报红，用计算展开成线段列表作为补法，按实际遇到再做。
- 控制点数上限是 32，与 Vulkan 相同，不构成缺口。

### 实现（10-21，tess 子线；上面的「Metal 原生曲面细分」在 Metal 4 上不成立）

**前提核对**：Metal 4 没有固定功能曲面细分。MTL4RenderCommandEncoder 没有 drawPatches / setTessellationFactorBuffer，MTL4RenderPipelineDescriptor 没有任何细分属性（SDK 26.5 头文件 + M5 Max 运行时探针，选择子全不响应）。所以「计算核写因子 → 固定功能细分 → 后细分顶点函数」这条只在 Metal 3 路径上有，主路径要自己展开。

**做法（gal_tess.m，Metal 3 / 4 两条路径通用）**，每次曲面绘制：
1. 顶点着色器按 SPIRV-Cross vertex_for_tessellation 翻成计算核（离线库键 = SPIR-V 键 ^ NXGAL_VT_SALT，gal_xc 对 `<键>.vt.spv` 出这个变体），属性按顶点自取表读，顶点号按本次绘制的索引 / 基顶点算；
2. TCS 翻成计算核（multi_patch_workgroup），写输出控制点、每片属性、细分因子（MTLQuad/TriangleTessellationFactorsHalf 布局）。TCS 要知道域才能定因子布局：Ryujinx 补丁 0092 tess-tcs-modes 让 TCS 的 SPIR-V 也带域 / 分区 / 绕序；
3. 细分器计算核：D3D11 参照细分器（gal_tess_d3d.h，Mesa 里 Microsoft 的 MIT 参照实现，C++ / MSL 双编）计数 → 单线程组前缀和 → 生成域点（u, v, w, 片号）与三角形 / 线 / 点索引，间接参数在 GPU 上写；
4. 普通索引间接绘制：TES 改写成普通顶点函数（按顶点号从域点缓冲取 gl_TessCoord / gl_PrimitiveID），片元不变。isolines 也能画（Metal 原生没有）。
阶段之间的控制点结构体按规范布局重排（32 个通用位置 + 位置 + 点大小 + 裁剪距离，每控制点 576 字节；每片属性 512 字节），单支着色器能单独翻、离线库按单支索引。

**读数（10-21，M5 Max）**：
- 细分器移植与 Mesa 原版逐点逐索引差分：20000 例（三种域 × 三种分区 × 四种输出图元，随机因子）全一致。
- 双后端对拍（tests/visual/tessref，我方 vs Ryujinx Vulkan @ MoltenVK 原生细分，256×256，颜色 / 位置都取 gl_TessCoord 的非线性函数）：8 个用例（四边形整数 / 非对称因子 / 奇偶分数、三角形整数 / 奇分数、剔背面、剔正面）差异像素全部 0.000%；错配用例反证 28.7–51.9%。
- 每次曲面绘制 GPU（1920×1080 目标，同帧多次绘制每次都要结束渲染通道）：我方 83–173 µs，MoltenVK 原生 32–69 µs；单次 1024 片我方 216 µs、MoltenVK 304 µs。
- 首个曲面程序建出时后台编细分器辅助库（Mac 约 130 ms，不用曲面的游戏不编）。

**还没做**：TES 缺 TCS（缺省细分因子）的程序照报红跳过；曲面绘制的计算段还没挪进预载命令缓冲（每次曲面绘制结束一次渲染通道，nxgal_tess_stats[2] 计数）；片元读 gl_PrimitiveID 时拿到的是展开后的三角形号，不是片号（未遇到）。

## 二、几何阶段：沿用 Ryujinx 自带的转计算，补上缓存和离线

Ryujinx 的翻译器已经有 VertexToCompute / GeometryToCompute 两个变换（给不支持几何着色器的后端用，MoltenVK 路径就在用），输出是计算着色器加普通的顶点 / 片元绘制。我们不另写，要补的是三件事：
1. **缓存**：Ryujinx 补丁，让加载器不再丢弃转计算的程序。宿主二进制（GALP）给计算段加阶段标记，加载时按二进制建程序。缓存版本 +1。
2. **离线配对**：shbake 按程序把「顶点 + 几何」配对后，离线跑同一个转换，翻译出 SPIR-V，再进 gal.metallib 和 Ryujinx 缓存。配对来源有两个：一是规则或冷局记录；二是对没配上的 gs，用游戏里同一着色器容器内的顶点着色器做静态配对，配对规则由出包统计验证。
3. **渲染器**：计算段结束和后面的绘制之间要加缓冲屏障。计算段同样尽量放进预载命令缓冲。

**10-21 实现与核对（gfxsh/gs）**：
- 缓存（补丁 vtg-compute-cache）：开局只登记（补丁 shader-cache-lazy），首次查找按需实化时认出复合二进制、建三个宿主程序、不翻译；复合宿主二进制放在 Ryujinx 层（魔数 S2AV：图形 / 顶点计算 / 几何计算三段各是原样的 GALP + 保留布局 + 直通顶点信息），**GALP 格式不变、不升 NXGAL_XC_VERSION**；CodeGenVersion 7354+4。上游阶段掩码「信息是计算就跳过」会让转计算程序读回错位，已改按程序类型判。
- 输入拓扑（补丁 gs-topology-match）：几何程序翻译读输入拓扑，上游匹配不比，已改为按输入拓扑类比；出包没有参照时几何程序按三角形烘。
- 屏障：编码器之间已是全阶段屏障（gal_core.m enc_barrier），同一计算编码器内相邻派发有 Dispatch→Dispatch 屏障；Ryujinx VtgAsComputeState 在顶点→几何、几何→绘制之间各调一次 Barrier（结束编码器）。读代码核过，不需另加。
- 预载命令缓冲：不挪。转计算每次绘制都用 SetBufferData 改同一块顶点信息缓冲（VertexInfoBufferUpdater.Commit，在录流内联上传），输出也复用同一环形缓冲，挪到预载会读到最后一次的值、互相覆盖；正确挪法要先把顶点信息改成按绘制分段（Ryujinx 侧），列后续项。
- 配对：片元阶段单独翻译（S2AStageIndep），转计算后的顶点 / 几何计算核与直通顶点只取决于（vs, gs）。规则一（gs 紧跟 ps、前面一串 vs，接口相容）、规则二（同容器读接口与 gs 写接口相同的 ps 唯一）出完整程序；规则三只出函数（vs 取 gs 前面最近的、写接口 == gs 读接口的那支，片元占位，不写缓存条目，运行时当场翻译但不现编）。

## 三、离线预编和判据

- **离线**：曲面的顶点核、TCS 核、后细分顶点函数都进 gal.metallib（gal.idx 记录 flags 新增「曲面」位）。基础管线也进 applegpu-nt 归档。所需的管线描述字段（tessellation 各项）由 pso_gen 从 SPIR-V 执行模式读出。
- **判据**（逐款跑纯静态冷局，不带参照包）：
  - `known_gap` 的 tess_unpaired、gs_unpaired、vtg_compute 三项都为 0；
  - shader_miss 为 0，xlate_n 为 0；
  - 曲面 / 几何程序录放对拍，与 Ryujinx Vulkan 参照逐像素比较（暗黑2 地形和巫师3 选固定帧）。
- **成本**：每次曲面绘制多一次计算派发，放在预载缓冲里。暗黑2 地形每帧绘制次数还没量，实测后再报 GPU 毫秒。

## 四、顺序（M1 之后）

1. 先做曲面细分：直接解锁暗黑2 地形（M4 暗黑2 全绿），一共 3 处改动——gal_xc 和 gal_prog 的三种入口、gal_state 的管线描述、gal_draw 的两步绘制。用 t_draw 补曲面单测：一个 quad patch 固定因子，期望三角形数可以手算。
2. 再做几何转计算的缓存补丁和离线配对，解锁马车8、八方2。
3. Metal 3 退路：曲面细分在 Metal 3 下 API 相同。转计算只用计算和普通绘制，两条路径都可用。

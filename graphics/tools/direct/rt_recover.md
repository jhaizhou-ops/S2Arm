# 现编回收清点工具（#281 R2-a）

`rt_recover.py` 在本机读取直连兜底目录和同版本游戏的出库缓存，生成给 R2-b 的回收表。输入必须是停止写入的快照；工具不修改输入、不编译、不联网、不把现编 MSL 放进离线库。

```bash
python3 graphics/tools/direct/rt_recover.py \
  --fallback /私有局/direct_rt \
  --direct-cache /私有缓存/程序号 \
  --tables /私有资源包/shaders/direct \
  --host-log /私有局/host.log \
  --out /新的报告目录
```

- `--fallback` 可重复。只把合法的 `<键>_b.json` 与对应源码作为现编线索；坏 JSON、缺文件、重复冲突均在报告中列出。
- `--direct-cache` 应含 `work/merged/union_keys.tsv`、`work/merged/shader_map.tsv` 和 `work/merged/pkg/`；出库失败原因从 `work/build.log` 找。
- `--library` 缺省是 `<direct-cache>/mac`，目录下应有 `b-<当前链>/`。只看当前链、非空 metallib 和匹配反射文件；这是库存清点，不是驱动加载验证。
- `--tables` 是对应离线库的表目录。当前链从本树 `graphics/nvn/gfx/nvn/dmsh_chain.h` 读取；`--chain-header` 可指定另一份头文件，主要供合成检查使用。
- `--host-log` 可省略。省略时只做清点，对拍记 `n/a`。提供时，成功序号、成功总数和唯一正常收局摘要必须齐全，并逐键关联成功事件；截断、超时收局或缺对应事件的条目保持「无法验证」。已有兜底文件不等于本局新现编。对拍还要求唯一有效库输入戳，见下节。
- 输出目录必须新建或为空，且不能在任何输入目录内。工具拒绝复用旧报告，避免把旧输出当本次结论。

## 回收表

`rt_recover.tsv` 的数据行固定五列，按键排序，每键一行：

```text
key  stage  chain  classification  comparison
```

实际分隔符为制表符。表头和最后的 `# summary {…}` 行以 `#` 开头，消费方应跳过。`rt_recover.json` 包含同一份行、计数、单局关联和逐键原因；报告仅保留元数据，不复制原料或 MSL 文件。

| 归类 | 含义 |
|---|---|
| `lib_miss` | 并集中有键，当前链库中有对应产物；运行时仍现编，应核包与库是否一致 |
| `build_fail` | 并集中有键，当前链库中没有可识别产物；附出库日志原因，缺原因时明确待核 |
| `extract_gap` | 已读取的合法并集清单没有本键，交 WP8；缺清单不能推断成抽取缺口 |
| `chain_skip` | 线索属于其他链，跳过并计数，不读取其源码或要求其原料存在 |

原料按 `merge_extract.py` 的记录与键口径重新核对，检查记录长度、控制段长度、阶段和重算键。原料损坏与同键冲突报红。多个目录含同键的同一产物时去重；当前链优先于旧链。库未出成与对拍结果是两件事：即使已有中间 MSL 对拍为 `same`，`build_fail` 仍需要 R2-b 处理。

## 对拍与库输入戳

`same` / `diff` 比较本机离线链现有 MSL 与现编 MSL 的逐字节内容，几何阶段还检查 `_bgN` / `_bgv` 产物集合。工具不重编离线链；重新出库和再跑游戏归 R2-b。`tests/dsh_cmp` 可继续用于编译器逐例对拍。

运行时每局会从使用的库读取 `b-<链>/inputs.tsv` 并写入日志，例如：

```text
shader library stamp: game 01006F8002326000, inputs 34546d73f94a
```

同链同键条目按以下顺序核对：

1. 日志必须来自本次兜底文件对应的单局，含完整成功事件、正常收局摘要和唯一有效库输入戳。
2. 日志中的程序号和输入指纹必须与当前离线库 `b-<链>/inputs.tsv` 相同。工具再用 `dmsh_chain.inputs()` 和官方 `Game` 解析器重算当前表输入摘要，核对离线库戳。
3. 事实表、配对表和派生片元输入表必须存在。摘要覆盖范围沿用离线链的 `inputs()` 契约；不另造历史表哈希。原料按控制段及代码重算键，核对长度与阶段。
4. 核对两侧完整 MSL 产物集合后逐字节比较。顶点配对片元还需两侧存在一致的 MSL；缺配对源码或几何产物时记 `n/a`。

运行时与离线链使用包内同套表，日志库戳用于绑定上下文。缺日志、缺戳、戳重复/有歧义、程序号或输入指纹不符、表或产物不全时记 `n/a`，不因 MSL 字节相同判通过。库目录和表必须对应实际使用的同版本包，不应混用不同包的日志和兜底目录。

本工具不要求、生成或读取 `rt_context.json`。旧版本实验留下的侧车不参与判定。

## 退出码与验证范围

- `0`：本次清点完成，没有输入错误、字节差异或未验证的当前链条目。可能只有异链跳过，不能据此宣称样本满足首局 N > 0 或游戏验收通过。
- `1`：输入错误、重复冲突、原料损坏或已确认的字节差异。不要把这份报告当作可直接出库的成功结果。
- `2`：清点有有效分类，但仍有 `n/a`、单局日志不完整或没有条目，需补证据。

纯合成回归：

```bash
python3 graphics/tools/direct/tests/t_rt_recover.py
```

测试不包含游戏数据，不执行着色器编译、GPU 或手机操作。本分片按维护者确认的「先合工具，正样本另单补」交付。真实首局 N > 0 → 回收 → 重新出库 → 同路线复跑及真实库戳下的逐例对拍，仍须在后续样本任务附实测证据。

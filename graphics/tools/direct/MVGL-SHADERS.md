# Media.Vision MVGL（MDB1）归档的着色器抽取（时空异客 / Cyber Sleuth）

> 2026-11-18。时空异客（010062E01FE0C000）接入后：抽取 84,790 对、**去重 19,922 个唯一键**
> （vs 6314 / ps 13606 / cs 2；Windows 出包机实测），此前本体 app_0.nx64.mvgl 一支也抽不出。
> Cyber Sleuth 的 MVGL 走 gl_shaders.py（.shad 文件）；本篇讲 S2Arm 抽取（nxsh_extract.py）侧的
> MDB1 归档直读与时空异客的两种条目形态。

## 归档格式（translator/mdb1.py）

Media.Vision 的 MDB1 有两种布局（SydMontague/MVGLTools 的 MDB1.h，BSD-3，对着时空异客归档实测确认），
小端、Switch 上明文，数据区偏移都相对数据区起，名字与树项按位置一一对应、经树项的数据号间接指到数据项：

| | 32 位（Cyber Sleuth） | 64 位（时空异客 / THL） |
|---|---|---|
| 头 | 0x14 | 0x20 |
| 树项 | 8 B {u16 比较位, u16 数据号, u16 左, u16 右} | 16 B {u32 同字段} |
| 名项 | 0x40 B {char ext[4], char name[0x3C]} | 128 B {char ext[4], char name[0x7C]} |
| 数据项 | 12 B {u32 偏移, u32 原长, u32 存储长} | 16 B {**u64** 偏移, u32 原长, u32 存储长} |
| 压缩 | doboz v0 | LZ4 裸块 |

数据表基址 = 数据区起 − 条目大小 × 条目数。64 位归档的偏移是 u64：按 u32 读时 4 GB 之后的条目
（时空异客着色器恰好都在 4–6.2 GB 带）全读错，见坑记录 11-18。

## 条目形态与扫描

MDB1 条目解出后交 `visit()`，着色器条目是「控制段 + 机器码」两种形态：

1. **相邻式**：`[0x40 头][NVN1 控制段 cn 字节][SPH + 机器码 dn 字节][NVASM 汇编文本]`——
   `scan_blob` 的相邻配对（HDR=78563412+12 零）直接出对；机器码是成品可直接翻译，
   汇编文本只是随包附带，不抽。
2. **NXFS 容器**（时空异客 app_0 里 28,354 支、全部 fragment）：0x40 头里 +0x0c 控制段偏移、
   +0x14 机器码偏移、+0x18 机器码长，控制段与机器码隔着 0x80 反射区，相邻配对够不着——
   `scan_nxfs` 按头里的偏移直读，全对上才认，对不上退回相邻扫描。

## 内存与取舍

- 大归档（时空异客 app_0 6.2 GB、176,835 条目、解压后 19.47 GB）**不整读**：`work()` 里
  顶层 MDB1 走 `romfs_list.open_file` 流式，`mdb1_visit` 逐条目解、逐个 visit，内存恒定；
  嵌套 / 小归档在 `visit()` 里整读递归。
- 同款 DLC / 补丁归档里的 `ounce64.mvgl` 是 Switch 2 / PC 变体（zstd 帧里是 SPIR-V），不抽；
  `shader_split.py` 对 MDB1 顶层文件直接跳过裸扫——ounce64 裸扫会配出控制段与代码区对不上
  的假键（直连库全数「NVN2 控制段长度不合」）。
- 归档里没有、真机首遇的着色器照旧走运行时现编（DM_NVN_SHDUMP 落盘回填），本改动只管
  抽得着的。

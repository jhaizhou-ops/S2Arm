# 16 KB 页精确写跟踪：设计与 Ryujinx 语义逐条对齐（帧率能耗线，10-19 v1）

## 要证明的事
GPU 侧缓存（贴图 / 缓冲 / 着色器 / 描述符池）在每次提交前知道「CPU 改了客体内存的哪些 4 KB」；GPU 改过、还没回写的数据既不被 CPU 的写冲掉，也不冲掉 CPU 的写。
Ryujinx 原版靠 CPU 模拟器的访存检查或宿主 4 KB 页保护得到这些；我们游戏直跑在真内存上、Apple 宿主页 16 KB，由本模块用 16 KB 页保护 + 缺页 + 内容比对，按 4 KB 子页给出同样的结果。

## 接口（s2a_track.h）
| 调用方 | 函数 | 对应 Ryujinx |
|---|---|---|
| C#（IVirtualMemoryManager 实现，服务接入线） | `s2a_track_reprotect(va, size, perm)` | `TrackingReprotect(va, size, protection)`，perm 原值 None / Read / ReadAndWrite |
| 同上 | `s2a_track_write(va, size)` | `Write` / `GetWritableRegion(tracked)` 等跟踪写之前的 `SignalMemoryTracking(write)` |
| 同上 | `s2a_track_write_untracked(va, src, size, flush)`（本模块代为复制） | `WriteUntracked`（GPU 回写 Flush：flush = 1；信号量 / 报告值：flush = 0） |
| 同上（提交前一次） | `s2a_track_drain(&batch)` | 把本批 CPU 写转成 `VirtualMemoryEvent(addr, size, write:true)`（ranges）与精确写（precise，见下） |
| 原生层信号处理 | `s2a_track_fault(addr, is_write)` | 宿主页保护的缺页处理 |
| 原生层 | `s2a_track_prot_changed(va, size)`、`s2a_track_write(va, size)` | `Map` / `Unmap` 后的重算；原生层自己写游戏内存 |

**一次跨界一批**：drain 交两张表（数组归本模块，零复制）——`ranges`（已合并的 4 KB 对齐脏区间）、`precise`（每个 NONE 子页一条 + 512 字节变动位图）。C# 先处理 precise、再处理 ranges。
旧库反例：逐段回调，暗黑2 一局 2039 万次托管调用（平均每段 5 字节），读回阻塞 4 → 1287 ms。

## 逐条对齐表
| # | Ryujinx 原版语义（Ryujinx.Memory.Tracking） | 本模块 | 状态 / 证据 |
|---|---|---|---|
| 1 | 跟踪粒度 4 KB（`MemoryTracking(pageSize = 4 KB)`） | 保护意图按 4 KB 子页记（`want` 位）；宿主页 16 KB 内任一子页要保护即整页只读 | 对齐；t_track ①② |
| 2 | `ReadAndWrite`：不跟踪 | 清 `want`；页内无要保护子页即整页可写 | 对齐；t_track ⑩ |
| 3 | `Read`：写即报脏（`RegionHandle.Signal(write)` → Dirty） | 被写子页记脏；同页其余要保护子页随整页解开，先记内容哈希，排空时内容变了才报脏、没变的重设只读 | 结果对齐（只多不漏：内容没变的写不报——原版会报，但没变即无需失效）；t_track ①② |
| 4 | Dirty 期间 `RequiredPermission = ReadAndWrite`，直到 `Reprotect` | 报脏子页的 `want` 交还 Ryujinx，它同步后自己再 reprotect | 对齐；t_track ④ |
| 5 | `None`（有 PreAction = GPU 改过）：CPU **读或写**都先跑 PreAction（Flush：回写 GPU 数据，等 GPU），然后写才记脏 | **写**：首次写前拍 4 KB 快照，排空时逐字节比，按位图报精确写；不回写、不等 GPU。CPU 写的字节以 CPU 为准，其余字节保持 GPU 改过——与原版「先回写再让 CPU 写」逐字节同结果 | 结果对齐（除第 6、7 条）；t_track ⑥–⑨ ⑬ ⑮。精确写在 C# 侧要落到 `Buffer` 的「GPU 改过区段」里打穿，见下「C# 侧」 |
| 6 | 同上 | 已知盲区：CPU 写入的值恰好等于客体内存旧值，比不出来，该字节保留 GPU 值（原版是 CPU 值） | 盲区，t_track ⑦ 钉住行为 |
| 7 | 同上，**读** | **不拦读**：CPU 读 GPU 改过、还没回写的字节读到旧值 | **缺口**。要拦读需把页设不可访问、缺页里同步调 C# Flush（Ryujinx 自己在宿主映射模式就是信号处理里调托管）；代价是读也缺页 + 等 GPU。先量：九款里 CPU 读 GPU 改过区段的次数（回放 / 局内计数），再定 |
| 8 | `WriteUntracked`（Flush 回写 / 信号量）不报脏；之后 CPU 写照样触发 | 本模块代为复制，写完的内容当基线（跟踪子页记写后哈希、GPU 改过子页的快照改成写入值）：写入本身不报，之后 CPU 写排空时比得出来。落到已在观察中的子页先比一次（变了 = CPU 写过，记脏）。已知窗口：别的线程恰在复制到记基线之间（微秒级）写同一 READ 子页会并进基线 | 对齐；t_track ③⑨⑯；对拍找到并修掉两处：旧设计「回写后重设只读不比内容」漏报、「观察中子页被信号量写」多报 |
| 9 | 原版次序：Flush 回写在 CPU 写之前 | 我们 CPU 写在前（延后到排空）：flush = 1 时写完把 CPU 先写、还没报的字节放回 CPU 的值；flush = 0（信号量 / 报告值，时间上晚于 CPU 写）以写入值为准 | 对齐；t_track ⑪⑫ |
| 10 | `Map` / `Unmap`：重算保护，未映射的句柄不报 | `s2a_track_prot_changed`：跟踪中的子页按脏报（内容可能换了），快照作废 | 保守对齐（多报不漏）；原生层调用点待接 |
| 11 | 事件在访存当时同步发出 | 延后到排空：GPU 线程处理每个 GPFIFO 命令前，若它入队晚于上次排空就先排空（GPFifoDevice.S2ATrackSync，补丁 0114）——游戏在入队之前的写都已变成事件 | 对齐（时序等价）。10-21 修前只在渲染循环唤醒时排空一次，DispatchCalls 接着取走排空后才入队的命令、拿 GPU 侧旧数据画（八方2 选项页屏闪：常量 / 顶点缓冲新旧混杂）；服务层单测「写跟踪排空」 |
| 12 | — | 快照池按需增长：每块 8192 槽（32 MB），满了缺页里 mmap 下一块，最多 8 块（槽号 16 位，256 MB）；排空时整块空了的附加块交还物理页。到顶仍满才退回普通脏子页 → Ryujinx 会先回写，**盖掉 CPU 已写的字节**（不等价，所以照报红）；每次报红带地址、计数 `pfull`，「写跟踪计数」行带槽满退回 / 峰值 / 块数 | 安全阀，不许静默；t_track ⑭（上限 1 块时退回）⑭b（增长、交还、交还后再用）。10-21 马车8 载入阶段一次连写超 8192 子页、修前 16+ 次退回 |
| 13 | — | 脏页环溢出（65536 页）：`batch.overflow = 1`，调用方按「全部跟踪区间都写过」处理并报红 | 安全阀 |
| 14 | 多线程并发：跟踪锁保证 | 缺页 / 写前 / 排空 / reprotect 间的次序：排空先设只读再比；遇正在解开的页（BUSY）等它落地 | t_track ⑤⑮ 并发 1 秒漏报 0（5 遍）；反向对照（旧库修前次序）1 秒漏报 142744 次 |
| 14b | 过期缺页：写缺页时页还只读、处理函数跑到时别的线程已合法解开（并发缺页解开 / Ryujinx 改不跟踪 reprotect RW / 自愈） | 跟踪表记可写时按**内核实际保护**（vm_region_64）判：内核已可写 = 竞争，重执行；内核不可写 = 外部改了保护没报 prot_changed，才自愈 + 报红（带 kprot）。不按「最近解开时刻」猜（旧判据不认 reprotect RW、处理函数被抢占超 10 ms 也误判成自愈，10-21 九款真机 / Mac 每局 1–28 行红、整页误报脏）。**Android 不读 `/proc/self/maps`**：只看 `lastp`（本模块最后设的权限）；客人 `SetMemoryPermission` 走 `s2a_track_set_guest_protection`，先占 BUSY 再 mprotect，缺页自愈也在同一页状态机上复核 `lastp`，外部只读不会被随后落地的自愈改回可写。`lastp=RW` 首次按竞争处理（还原 PG_RW、`g_races++`、重执行，不 mprotect、不报脏），同一页连续第二次（`reject[]` fetch_add != 0）才自愈；`lastp` 不是 RW（0xfe 外部改过 / 0xff 未知）不升权：首次重执行，再缺页返回 0，安卓 on_crash 会 `_exit(128+sig)`（不是回原信号处理函数）。`backing_reset` 与 reprotect 发布状态时清 `reject[]`，避免上一代的计数把下一代的首次过期缺页直接判死 | t_track ㉓：过期缺页不自愈 / 算竞争 / 不报脏（改前自愈 +1、报脏 1 段，3 项红）；正对照外部 mprotect 只读仍自愈、整页 4 子页报脏。Android：tracking_test `PG_RW可恢复缺页且信号不打开文件`（信号里 open 计数 0）、`外部明确只读页不可升写`（SIGSEGV）；failure_test 可控竞态（自愈占页时 SetMemoryPermission(RO) 必须等它落地，旧序列红 / 新 API 绿） |

## C# 侧（服务接入线实现 IVirtualMemoryManager 时照做，进 Ryujinx 改动清单）
- `TrackingReprotect(va, size, protection, guest)` → `NxTrack.Reprotect`：只有 **guest = true**（游戏侧保护域：游戏代码直接访存的那份映射，对我们即唯一真实映射）交 `s2a_track_reprotect`；
  guest = false（普通域：服务 / GPU 经内存管理器的托管访存，Ryujinx 用软件页表判、不碰页保护）忽略——GuestMemory 对托管写一律发事件，等价于全程跟踪。
  依据：Ryujinx.Cpu MemoryManager / MemoryManagerHostTracked 的 TrackingReprotect 两域分开（10-19 M0 局之前两域都落到同一份页保护、后到覆盖先到，报过红）。
- 托管写一律照原版「跟踪事件由托管代码同步发，写本身不被游戏侧页保护当 CPU 写捕获」，不许由本模块在下次排空时重报（10-21 怪猎：重报晚于同批 GPU 命令，
  Ryujinx 那时若已给同 4 KB 挂了回写动作，每次重报都等一次 GPU 回写；还会把 GPU 之后写的字节盖回）：
  · Write / Write<T>：先 SignalMemoryTracking(写)，内容交 `s2a_track_write_untracked(flush = 0)` 代写（解保护、写完的内容当基线）；
  · WriteWithRedundancyCheck（常量缓冲内联更新）：区间所在子页没有 GPU 改过的（`s2a_track_gpu_modified` = 0）照原版比内容、变了才写；
    有则不回写，发精确写事件（缓冲按字节打穿「GPU 改过」并记脏）+ 代写 flush = 0，返回 true；
  · GPU 自己写游戏内存（贴图回写、清缓冲填充：Ryujinx PhysicalMemory 的不跟踪 GetWritableRegion，调用方都 using）：补丁 0110 给副本，Dispose 时经 WriteUntracked 写回
    （紧跟精确写信号的清缓冲 flush = 0，贴图回写 flush = 1），同 Buffer.FlushImpl；
  · 服务的不跟踪 GetWritableRegion（多数调用方不 Dispose、当游戏内存视图用）：直视图，事先 `s2a_track_write_quiet` 只解保护记脏、不触发先回写；
  · 调用方拿到引用 / 区域后自己写的 GetRef、GetWritableRegion(tracked: true) 仍先调 `NxTrack.Write`（= `s2a_track_write`）解保护并记脏。
- 每次 GPU 提交前 `s2a_track_drain` 一次：
  1. 先 precise：每条 = 一个 4 KB 子页 + 字节位图。对该子页内的 `Buffer`：只把位图标到的字节从「GPU 改过」里打穿、记脏（Ryujinx `Buffer` 的 PreciseAction 路径）；**没被 GPU 改过的字节整段算脏**（多传一次相同数据，无害）；两段之间的空隙不许合并成 CPU 写（空隙可能正是 GPU 改过、还没回写的字节）。贴图（不是缓冲）按原版普通事件处理。
  2. 再 ranges：`VirtualMemoryEvent(addr, size, write: true, precise: false, exemptId: null, guest: true)`——游戏写的事件发给游戏侧区域（精确写那步同样 guest: true）。
  3. `overflow` = 1：对全部跟踪句柄 `ForceDirty` 并报红。
- `WriteUntracked(va, data)` → `s2a_track_write_untracked(va, data, len, flush)`，由本模块复制（不要自己再写）；GPU Flush 回写 flush = 1，信号量 / 报告值 flush = 0。
- 跨界次数判据：每次提交 1 次 drain；每帧 alloc_kb 0（批数组复用）。

## 对拍（tests/ryucmp，`bash graphics/track/tests/ryucmp/build_run.sh <种子> <轮数>`）
同一随机访存序列喂两份 Ryujinx 原版 MemoryTracking（锁定版本 compat/tree 的 Ryujinx.Memory 源码）：参照 = 4 KB 权限模型、CPU 写时按权限同步发事件（原版 CPU 侧行为）；
我方 = TrackingReprotect 转本模块、CPU 写走真内存真缺页、提交前排空一次再发事件（精确写按 Buffer 合并：位图字节 CPU 值、其余 GPU 数据）。
每轮 CPU 阶段（1–11 次 1–8 字节写，可跨子页 / 跨页，值避开已知盲区）→ 排空 → 比 → GPU 阶段（同步 / GPU 改写 = 登记回写 / 信号量写）→ 比；比 64 个 4 KB 句柄的 Dirty 与 256 KB 逐字节。

# J09-S0 revision 准入与游戏进程

S0 是实验片，不代表 M2 手机内准备或正式通用 App 已完成。按 #493 总指挥调整，
基于 `android/integration@39684d54` 开发，先入 integration，再随 T02 列车进入 main。
不改 T05 make_pack / JNI 改写库，不接尚未合入的 T07 PlayerKeys；S0 只消费已经激活的宿主产物。

## 准入与签收

`GameSession.load` 在任何 guest 执行前重新读取 `current.json`、artifact 和 index。
保留 BootContract 的平台、guest ABI、改写 ABI、路径及必需文件检查；额外要求：

- `contentRoot == sha256-<index SHA>`，artifact 的 index SHA / 文件数 / 总字节与清单一致；
  每个索引文件的实际大小和 SHA 一致，revision 内除根目录 manifest/index/当前 artifact
  元数据外的每个文件均须在清单内，拒绝目录链接。允许 importer 的合法 CAS 文件链接。
  NPDM、control 必须在清单内；不能把元数据作为 NPDM。
  邻接 addr_need.tsv 可选：index 列出时必须存在并核大小/SHA；未列出时磁盘也必须没有，
  沿用 runtime 既有缺省语义。不得通过强制存在改变现行合法包格式。
- runtime 兼容版本为 `0.1.0`，改写器合同身份为现有生产者输出的
  `runtime/rewriter@android-sp-safe-v1`。这是兼容身份，尚不是精确改写器提交或签名来源证明。
- revision 起局只允许 debuggable APK 且冷启动显式传入
  `s2arm.experimental_revision=true`；缺省或 release 均明确报红，不换用 APK 模块。
- APK 来源仍核包名、versionCode、当前签名证书、完整 APK SHA，拒绝 split APK；
  模块路径、fixups ABI、target 与实际资产存在性同样检查。不接受混合来源或 widen。
- `FrozenStart.moduleSha256` 给出实际执行模块摘要，两种来源均记录到 S2Arm 日志。
  同 SHA 只证明模块字节相同，不能证明两个来源达到同一游戏里程碑。

| 合同 | 签收方（#493 owner 拍板） | 当前状态 |
|---|---|---|
| contentRoot 与内容身份 | 运维线 | 待签 |
| 改写 ABI / 改写器兼容身份 | 原生层线 | 待签 |
| revision 可执行来源 / 正式发布准入 | 交付线 | 待签 |

不把自校验 JSON 当作可信签名；正式来源认证、精确工具提交身份和生产放开须对口另行签收。

## 生命周期

`LibraryActivity` 是 launcher，只展示、导入与发起选定 title，不加载 native runtime。
`GameActivity` 复用原 MainActivity 的 runtime、输入、HostApi 和 Surface 接线，位于私有
`:game` 进程与独立 task，singleTask，不导出。MainActivity 的旧 per-game 入口转发至它，
通用包的 MainActivity 诊断入口保留。
自动化可经旧 MainActivity 显式传 `s2arm.title_id=<16位大写ID>` 转发选定游戏，
revision 同时需上述实验开关；不公开 GameActivity。

库 Play 经活动回执核对真实 PID、title、contentRoot、artifact SHA 与 session，再把原 task 带回前台；
不同局、revision 已变或退出中的进程报红拒绝。冷起局与恢复均走真实 Play 按钮。
游戏子进程只读取明确选择的一款；二次 Intent 不能换成另一款。BACK / finish / HostApi stop /
Activity 销毁走现有 native shutdown；初始化失败且未创建 native host 时只退出本子进程。
Surface 仍通过原 window lease offer / update / revoke，revoke 成功后才写 detached 回执；
超时沿用 native 失败退出，不记退休成功。`cache/game-lifecycle-<pid>.tsv` 是实际回调诊断，
不是 guest/画面/资源释放证明；资源收尾还要核 native 正常退出码与旧 PID 消失。

`GameStorage` 的进程间独占锁从准入持有到游戏进程退出。App 的 import / sweep 使用同一把锁，
忙时拒绝，防止运行中 revision 被裁剪；失败准入释放锁。锁内文件为 App 私有、不可变产物，
native 模块 callback 在复制完成后，对将交给 loader 的稳定内存核对冻结大小/SHA，
覆盖 image/fixups/gates；同 UID 替换路径、写同 inode 都拒绝，不会记录旧摘要却消费新字节。
NPDM 与已列出的 addr_need.tsv 在准入和起局前各核大小/SHA；未列出的表在两处均须维持磁盘不存在；按总指挥返工签收的范围决定，
两次核验与共享 native fopen 之间仍存在同 UID 替换窗口（包括服务层对原目录的读取）。
它不是已消除的 TOCTOU；后续需要 Android 已验输入读取接缝及原生层签收，不在 S0 扩改共享 loader/svc_mem。
也不承诺抵御根目录重命名、资源目录在准入后被同 UID 绕锁改写或恶意替换活动回执。
进程内先拦截重复取锁，避免失败的第二个 fd 关闭后释放原 POSIX 锁。

## 验证入口与限制

主机：`bash android/gate.sh`（真实 JDK17）。新增
GameSessionAdmissionTest 通过 GameInstall → GameSession.load，使用自造字节覆盖两来源相同
模块 SHA、索引外 NPDM/RomFS/systemdata、身份负例、缺省关闭、失败释放、跨 JVM 锁与恢复身份。
`verified_source_test.py` 提取真实 native callback，宿主 JNI 连接真实 Java 摘要校验，
对 image/fixups/gates 分别做路径替换与同 inode 写入；不执行 guest。manifest 检查只证明静态配置与登记。

设备 instrumentation：构建测试 APK 时设置
`-Ps2arm.nativeMode=game -Ps2arm.testRunner=org.s2arm.android.GameSessionLifecycleInstrumentation`；
不指定 gameDir 可构建通用包名，nativeMode 缺省仍为 diagnostic。在已装好 runtime、
已导入合法 revision 的 debug App 上传 instrumentation 参数 `titleId=<16位大写ID>`。
测试显式开启 revision，从 launcher 进入 Library，点击实际 Play accessibility action，连续两局；
同局后台后再点击 Play，断言 PID 不变；两局之间断言不同 PID、后台 Surface revoke、前台新 generation、
同进程只启动一次 guest、旧 PID 退出且 ApplicationExitInfo 为 EXIT_SELF/status0、APK SHA 与安装时间不变。
需 API30+；必须经设备租约运行，不能用 host 检查替代。失败时发送正常 finish，不杀其它进程。

测试在 `tools/contrib_layer2.tsv` 登记，仓库入口（需安装好的真实 game runtime 与私有数据）：

```sh
python3 android/tests/t_game_session_lifecycle.py --serial SERIAL --package PACKAGE \
  --title-id TITLE --content-root sha256-INDEX_SHA --artifact-sha256 ARTIFACT_SHA \
  --test-apk MATCHING_TEST_APK --out NEW_EVIDENCE_DIRECTORY
```

入口使用统一 canonical Lease/Adb，核私有 current 身份，只装匹配测试 APK；缺输入 exit2，
不能记通过。收尾核游戏与录屏清零，强制结束 child 一律失败。通用 runner 不替换主包，
具体游戏用后基线恢复由设备手册规定。主机 gate 核第二层登记与缺输入拒绝；设备测试同时在
`tests/test_wired_ok.tsv` 写明私有数据理由，不把它伪装为主机执行。

本机 diagnostic APK、测试 APK 与 lint 已构建通过；不碰设备，instrumentation 尚未执行。
正式 game/Docker APK 和另派设备验收仍须：
同一输入两来源的模块 SHA / 同一里程碑、原生退出日志与资源退休、连续两局不重装、
Surface 前后台恢复、各拒绝输入的可见红态；实际 gameplay、画质、性能与功耗另记。


## 冷启动切后台与恢复

`started`回执仅表示native worker接受启动请求，不是guest/GPU ready。首Surface在异步装载后才消费；若此时外壳在后台，等待同租约的下一可用foreground generation，释放/ACK尚无Vk对象的撤销take。GPU启动30s预算不跨后台冻结或producer epoch切换；真正连续前台卡住仍失败。

生命周期instrumentation分别在worker接受后立即切回Library、以及观察到真实queued present后切回Library，再经真实Play恢复；各阶段保持PID/session、产生新Surface代次，恢复后还要看到新的真实queued present。debug测试extra才开启私有present回执，正式UI无额外采样；present计数只有native GUEST_RUNNING后才读托管counter，避免诊断提前初始化NativeAOT。queued present不代表显示引擎实际显示或游戏里程碑。
